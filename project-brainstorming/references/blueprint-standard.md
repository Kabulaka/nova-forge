# 项目蓝图规范

## 1. 文档职责

`PROJECT_BLUEPRINT.md` 是所有模块和开发会话共同读取的项目宪法，不是功能需求全集。它回答：项目为什么存在、模块如何分工、哪些跨模块契约和全局不变量始终成立、系统有哪些架构红线、尚有哪些工作包未完成。

蓝图只保存项目级稳定事实：

- 项目定位、目标和非目标；
- 技术硬约束、代码结构和模块职责；
- 跨模块业务规则、公共外部契约和全局状态不变量；
- 共享的安全、资源生命周期和非功能要求；
- 项目级开发边界和系统架构红线；
- 待开发工作包索引、设计依据、依赖和完成定义。

以下内容不得在蓝图展开：

- 单个功能的页面、字段、局部交互流程或局部状态机；
- 单个故事的权限矩阵、异常分支、恢复步骤和详细验收；
- 具体函数、SQL、内部算法、迁移步骤和运维命令；
- 已完成阶段、提交记录和可从代码恢复的功能说明。

具体功能设计进入 `docs/design/*.md`，当前实现细节以代码、测试、迁移和配置为准。

## 2. 规范版本

当前规范版本为 `2`。蓝图标题后必须包含：

```text
> 蓝图规范版本：2
```

版本缺失或不一致表示需要迁移。不得仅凭标题和章节相似度认定兼容，也不得在未告知用户的情况下自动改写。

## 3. 推荐结构

参考紧凑的项目宪法结构，一级章节按以下职责组织：

1. 项目定位；
2. 技术栈；
3. 代码结构；
4. 模块架构；
5. 跨模块契约；
6. 待开发功能；
7. 系统架构。

章节可以增加项目语义前缀或在内部增加子章节，但一级职责和顺序必须保留。项目级开发边界、非功能要求、失败与资源约束放在“跨模块契约”或“系统架构”内；不得为了满足目录而复制同一规则。

## 4. 内容分流闸门

讨论结论满足任一条件时，提炼后进入蓝图：

- 多个模块必须共同遵守；
- 改变模块职责或依赖方向；
- 改变全局权限、安全、数据生命周期或状态不变量；
- 改变公共外部契约、项目级 SLO 或架构红线；
- 后续所有相关功能都必须遵守。

只影响一个史诗或工作包的交互、局部状态、异常恢复和验收时，只进入设计文档。全局规则的动机和局部应用留在设计文档，蓝图只写抽象后的规范，双方用链接建立追溯而不复制全文。

## 5. 待开发功能表

蓝图使用以下表头：

```markdown
| 编号 | 优先级 | 功能 | 设计依据 | 前置依赖 | 完成定义 |
|------|--------|------|----------|----------|----------|
```

约束：

- 编号必须稳定且唯一，不随优先级或排序变化；
- 设计完成的工作包必须引用 `docs/design/*.md` 的显式稳定锚点；
- 多个工作包可以引用同一设计文档的不同锚点；
- 尚未澄清时“设计依据”写“待澄清”，不得创建空链接或虚构设计；
- 设计依据只能指向尚未完成的真实工作包；指向“已完成”或“已废弃”工作包的待办无效；
- 前置依赖只填写当前待开发表中已确认的待办编号、`无` 或 `待澄清`；多个编号使用 `、`、`,` 或 `，` 分隔，不得自依赖；
- 完成定义保留可执行的外部结果，不在表格重复详细验收步骤；
- 工作包完成并通过项目验收后从表中删除，设计文档继续保留。

引用使用相对路径和锚点，例如：

```markdown
[语义化需求设计 WP-02](docs/design/semantic-requirements.md#wp-02-review)
```

不得使用行号作为引用目标。

## 6. 单一事实来源

| 信息 | 唯一事实来源 |
|------|--------------|
| 项目级边界、跨模块契约和全局不变量 | `PROJECT_BLUEPRINT.md` |
| 史诗公共语义和工作包行为设计 | `docs/design/*.md` |
| API 路由、DTO 和字段 | 接口规范或契约测试 |
| 数据表、索引和迁移 | 迁移代码 |
| 配置默认值 | 真实配置文件和配置校验 |
| 操作、备份和回滚步骤 | 运维手册 |
| 当前实现结构 | 源代码和测试 |
| 完成历史 | 版本控制和发布记录 |

发现重复事实来源时先确定权威位置，再删除重复叙述或改为链接。

## 7. 完成检查

- 存在规范版本 `2` 标记；
- 一级章节职责和顺序完整；
- 蓝图中的规则确实需要多个模块或所有后续工作共同遵守；
- 单个功能的详细行为、失败分支和故事验收已经分流到设计文档；
- 模块职责不重叠，依赖方向和架构红线明确；
- 全局权限、安全、数据、资源和非功能要求可验证；
- 项目级五类开发边界完整；
- 待办编号唯一，完成定义未因迁移被改写；
- 每个非“待澄清”设计依据均指向存在的文件和显式锚点；
- 已完成工作不留在待开发表中；
- 文档不复制可从代码、配置或版本控制恢复的细节。
