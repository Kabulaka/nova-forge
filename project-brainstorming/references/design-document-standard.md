# 史诗设计文档规范

## 1. 文档职责

`docs/design/<epic>.md` 保存一个史诗的公共语义和一个或多个相互关联的工作包。它负责承载具体功能的行为、权限、局部状态、失败恢复、依赖和验收，避免把这些内容注入所有开发会话共同读取的蓝图。

设计文档不是当前代码说明书。函数、SQL、完整文件清单和逐步运维操作仍以代码、测试、迁移和手册为准。

## 2. 状态与元数据

文档标题后必须包含：

```text
> 设计状态：澄清中
> 关联待办：WP-01、WP-02
> 必读范围：PROJECT_BLUEPRINT.md、本文件“公共上下文”、当前工作包章节及其直接依赖
```

设计状态只允许：

- `澄清中`：仍有工作包未完成需求确认；
- `已确认`：所有计划工作包的设计已经确认，但尚未全部实现；
- `已实现`：全部工作包已通过实现验收；
- `已废弃`：设计已被替代，必须指出替代来源。

状态为“已废弃”时还必须提供可定位链接：

```text
> 替代来源：[新设计](replacement.md)
```

每个工作包单独记录 `待澄清`、`澄清中`、`已确认`、`开发中`、`已完成` 或 `已废弃`。文档总状态不得掩盖工作包差异。

- 仍有“待澄清”或“澄清中”工作包时，文档状态必须为“澄清中”；
- 全部工作包已经确认且仍有未完成工作包时，文档状态必须为“已确认”；
- 全部工作包均为“已完成”或“已废弃”且至少一个为“已完成”时，文档状态必须为“已实现”；
- 文档整体被替代时优先标记“已废弃”，全部工作包必须为“已废弃”，并提供替代来源；
- 全部工作包均为“已废弃”但没有替代来源不是合法终态：必须补充替代来源并把文档标记为“已废弃”，不能标记为“已实现”。

## 3. 公共上下文

公共章节只保存所有工作包共同需要的内容：

- 问题、目标和明确非目标；
- 共享领域模型、术语和数据关系；
- 共同权限、状态和业务不变量；
- 工作包地图、前置依赖和组合验收；
- 与蓝图中全局契约的链接。

公共上下文必须使用显式稳定锚点：

```html
<a id="shared-context"></a>
```

如果两个待办不共享这些内容，拆成不同设计文档，不能为了减少文件数量强行合并。

## 4. 工作包章节

每个可独立开发和验收的故事使用稳定 ID 和显式锚点：

```html
<a id="wp-01-semantic-extraction"></a>
## WP-01 语义化要求提取
```

工作包章节必须覆盖：

1. 状态、范围和非目标；
2. 前置条件、输入、输出和外部可观察结果；
3. 正常行为、权限和局部状态变化；
4. 边界、失败传播、重试、回滚、清理和恢复责任；
5. 与其他工作包的依赖和受影响模块；
6. 可执行验收，包括正常、失败和必要的组合场景。

只有当前工作包确实需要的内容才进入该章节。公共规则使用链接引用，不复制全文。

## 5. 锚点和引用

- 蓝图只引用显式 HTML `id`，不得引用行号；
- 锚点在工作包完成后仍保持稳定；
- 修改标题不得顺带修改既有锚点；
- 一个蓝图待办只能引用一个主工作包章节，额外资料由该章节继续链接；
- 多个待办可以引用同一文件的不同锚点。

## 6. 澄清写入规则

用户确认开始澄清后，可以创建“澄清中”文档以保存长会话成果，但必须分离：

- 已确认要求；
- 有来源的证据推断；
- 尚未决定的差量。

证据推断和未决项不得使用“必须”“不得”伪装为正式要求。工作包完成局部闭环并由用户确认前，蓝图设计依据仍保留“待澄清”。

## 7. 开发会话读取范围

开发某个工作包时只要求读取：

1. `PROJECT_BLUEPRINT.md`；
2. 本设计文档的元数据和公共上下文；
3. 当前工作包章节；
4. 当前工作包直接依赖的章节。

必读范围不得写成整份史诗、全文、全部工作包或所有工作包。除非需要处理组合验收或发现冲突，不加载其他无关工作包的完整内容。

## 8. 生命周期

- 新澄清建立或更新“澄清中”文档；
- 工作包确认后更新其状态并把蓝图待办链接到对应锚点；
- 工作包实现并验收后从蓝图待开发表删除，设计章节改为“已完成”；
- 仍有其他工作包时文档继续保留并保持可引用；
- 全部工作包均为“已完成”或“已废弃”，且至少一个为“已完成”时，文档标记“已实现”；
- 新设计取代旧设计时，旧文档标记“已废弃”并链接替代文档，不静默删除历史决策。

## 9. 完成检查

- 文档状态和每个工作包状态一致；
- 公共上下文确实被多个工作包共享；
- 每个工作包有唯一、稳定的显式锚点；
- 行为、权限、失败恢复和验收形成局部闭环；
- 依赖和组合验收明确；
- 蓝图中的引用能解析到真实文件和锚点；
- 没有把证据推断或待确认内容写成正式要求；
- 没有复制蓝图全局规则或代码可恢复细节。
