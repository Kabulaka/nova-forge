# 订单平台 — 项目蓝图

> 蓝图规范版本：3
> 文档定位：定义所有模块共同理解并长期遵守的项目级事实，以及尚未完成的工作包索引。
> 事实来源：待开发目标以设计工作包为准；当前实现以代码、测试、迁移和配置为准。

## 1. 项目定位

| 对象 | 问题 | 成功结果 |
|------|------|----------|
| 订单与履约团队 | 多人并行开发时公共边界不一致 | 订单提交和履约功能可基于稳定契约独立交付 |

## 2. 技术栈

| 类别 | 当前事实或硬约束 | 事实来源 |
|------|------------------|----------|
| 语言与框架 | Python 3.13 / FastAPI，单体模块化服务 | `.nova/architecture/foundation/project-skeleton.md` |
| 持久化与缓存 | PostgreSQL；本期不使用缓存和 MQ | `.nova/architecture/foundation/project-skeleton.md` |
| API | OpenAPI 3.1 | `.nova/architecture/api/openapi.yaml` |
| 鉴权与部署 | OIDC Bearer Token；OCI 容器单实例起步 | `.nova/architecture/foundation/project-skeleton.md` |

## 5. 跨模块契约

### 全局契约

| 契约 | 适用范围 | 验证 |
|------|----------|------|
| C-01 | 所有模块通过订单 API 访问订单，不跨所有者写数据 | 契约测试 |

### 开发决策边界

| 边界 | 内容 |
|------|------|
| 本期必须实现 | 订单创建和履约查询 |
| 明确不做 | 支付和物流调度 |
| 后续候选 | 订单事件流 |
| AI 可自行决定 | 模块内部函数和文件拆分 |
| 必须再次确认 | 公共 API、数据所有权和状态变化 |
