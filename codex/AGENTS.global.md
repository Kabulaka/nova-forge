# 全局工作约定

## 技能路由

- 只有用户明确要求澄清、新增、查看、修改或删除业务需求时才使用 `nova-requirements`；其他技能不得自动转入本技能，也不得主动发现、读取、索引、校验或同步需求文档。
- 判断蓝图是否存在时直接检查固定路径 `.nova/PROJECT_BLUEPRINT.md`（如 `test -f`）；禁止用会忽略隐藏目录的 `rg --files`、目录扫描或索引结果代替存在性检查。
- 项目不存在蓝图时，由 `nova-architecture` 负责初始化；蓝图存在后，只有用户主动调用该技能，或明确要求改变技术栈、运行形态、基础设施职责、系统分层、稳定目录、项目级服务/模块职责、所有权或依赖方向时才修改架构。
- 业务 API、业务 schema、DTO、数据库表、业务事件和端到端功能流程即使跨多个模块、有版本或兼容要求，也默认属于 `nova-development`；只有其中确实改变系统骨架的最小差量先交 `nova-architecture`。Development 不得自行修改蓝图中的系统骨架。
- 任何代码、配置或测试的实现、调整、修复和维护均使用 `nova-development`；请求明确时直接实施，只有真实歧义才澄清。
- Requirements 在用户明确要求需求澄清或创建、修改内容不足时使用 `skills/nova-development/references/conversation-sop.md`；Architecture 与 Development 在发生真实歧义时使用同一文件，不得各自维护不同的澄清协议。
- 原生结构化提问只是交互载体，不承担宿主权限审批；出现 2–3 个真实互斥选项且当前交互通道支持时，可选选择和阻塞选择都允许按共享澄清 SOP 使用。问题是否阻塞只决定无有效答案后的推进方式，不决定能否调用工具。
- 只有用户明确要求 Review、审查、复审或补审时才使用 `nova-review`；加载技能本身不代表获得审查授权。
- 只有用户明确要求创建本地提交时才使用 `nova-commit`；Architecture、Development 与 Review 不得创建提交或自动转交 Commit。
- `nova-commit` 只能消费进入技能前已有且有效的验证证据；准入失败立即结束，不得自行调用其他技能制造证据后继续提交。
- 技能只在命中时加载；本文件只负责跨技能路由和共同边界，具体流程由对应技能定义。

## 技能控制文档加载

每次新的用户请求均重新判断技能路由。命中技能后完整读取其 `SKILL.md` 及当前分支直接要求的控制文档；工具明确截断时从未返回位置续读。同一会话的同一内聚任务再次命中同一技能时，直接复用已经完整读取且未发生变化的内容，不得只因进入新的对话轮次而重复读取；只有任务目标或范围使路由发生变化，或控制文档已被修改时，才加载新增或变化内容。不为证明已读而额外计算哈希或制造工具往返。

已安装技能及其控制文档位于项目根目录之外，且已知上下文处理工具受项目根目录限制时，直接使用宿主允许的原生只读方式完整读取，不先执行必然失败的项目内文件分析调用；项目内代码、日志和大型输出仍按对应工具规则处理。

## 上下文压缩与续接

1. 续接信息保留当前目标与阶段、用户已确认决定、明确排除、AI 候选、未决差量、活动范围、有效证据、文件状态和下一动作；不得把候选或未知提升为用户确认。
2. 先从会话和工作区恢复缺口，仍会改变结果时只询问一个具体差量；不得保存秘密，新会话不自动继承旧任务。

## 事实、文档与工作树

1. 当前实现事实以代码、测试、迁移和配置为准；蓝图一次保存系统骨架、已实现可复用能力和待开发工作，只有系统骨架属于架构；设计只保存用户明确要求沉淀的局部目标与契约。
2. 不主动扫描、枚举、通配匹配或索引 `.nova/design/`；只有蓝图为当前任务给出精确设计链接时，才读取对应设计及其直接依赖。
3. 蓝图“已实现可复用能力”是通用组件的唯一发现入口；新旧蓝图读取时兼容旧标题“开发导航”，只读取本次命中的精确实现和验证入口。业务流程、业务契约和潜在复用候选不得登记。
4. Architecture 只维护系统骨架；Development 在当前任务实际交付并验证通用组件时同步维护“已实现可复用能力”，不得为此扫描历史代码或自动转入 Architecture。
5. “待开发工作”只保存大块开发需求和需要独立处理的真实技术债务；设计入口为“无”表示尚未沉淀设计，精确链接表示设计已确认。Development 在用户明确要求拆分、设计或登记时维护相关条目，Review 只在最终结论后登记符合准入的技术债务；完成后删除条目，设计文件保留。
6. 开始修改前固定任务范围和既有工作树；不得覆盖、回退、暂存或夹带用户已有修改。无法可靠分离时停止并只询问范围差量。
7. 同一失败重复且没有新证据或新方案时停止，报告已验证事实和阻断点，不以放宽契约、吞错或隐瞒失败换取通过。

## 流程边界

- Nova 不维护需求块、交付台账、审计、检查点、迁移或 Review 状态。
- Requirements、Architecture、Development 与 Review 的结果均保持未提交；只有用户明确发起 Commit 后才创建本地提交。
- Plan mode 只由用户启用，方案批准前不得编码；Plan mode 不自动启动 Review 或 Commit。
- Git push、远程配置、发布和 SVN commit 必须取得独立明确授权。
- 始终服从“当前用户明确指令 > 项目规则 > 本文件默认规则”。
