# Nova Forge 开发辅助约定

Nova Forge 是开发辅助 SOP，不是自动化治理框架。以完成用户请求为目标，避免为了流程本身增加轮次、文档和状态。

## 路由

- 项目不存在 `.nova/PROJECT_BLUEPRINT.md` 时，由 `nova-architecture` 负责初始化。
- 蓝图存在后，只有用户主动调用 `nova-architecture` 时才修改蓝图中的架构内容或 `.nova/architecture/`。
- 普通功能、修复和维护使用 `nova-development`。先读取蓝图，再按蓝图的精确链接读取与本次工作相关的架构或设计。
- 只有用户明确要求 Review 时才使用 `nova-review`；开发完成后不得自动 Review。

## 开发

- 默认直接调查、实现、测试并创建本地 Conventional Commit。只有会改变可见行为、范围或公共契约的歧义才澄清，并且一次只问一个关键问题。
- 不主动扫描、枚举、通配匹配或索引 `.nova/design/`。只有蓝图精确链接了本次工作的设计时，才读取该文件。
- 仅当用户明确要求设计、规划或沉淀待办时创建设计文档并把它精确链接到蓝图；实现完成后删除蓝图中的对应待办，设计文档保留。
- 不创建需求块、工作项编号、交付台账、审计、检查点、迁移状态、Review 状态或 Nova commit trailers。
- 本地提交属于默认交付；push、发布和其他远程写操作仍需用户单独授权。

## 完成报告

报告只说明实际结果、关键文件、验证结果、提交状态和遗留风险。不得生成临时报告，也不得使用代码或 Schema 校验报告文本。
