# Nova 开发

目标是像普通开发一样直接，只增加蓝图约束和必要澄清。

## 开始

1. 找到仓库根并读取 `.nova/PROJECT_BLUEPRINT.md`。若不存在，转由 `nova-architecture` 初始化后继续。
2. 只读取蓝图中与当前改动直接相关的架构链接。
3. 禁止扫描、枚举、通配匹配或索引 `.nova/design/`；只有蓝图对当前待办给出精确链接时才读取对应设计。
4. 调查代码和测试，以代码事实确定最小交付范围。

## 澄清

- 能从请求、蓝图和代码确定实现时直接开发。
- 只有歧义会改变用户可见行为、范围、数据或公共契约时才澄清，一次只问一个关键问题。
- 不进行例行需求访谈，不为已经明确的请求重复确认。

## 设计与待办

- 只有用户明确要求“设计”“规划”或“沉淀待办”时，才使用 [设计模板](assets/DESIGN.template.md) 创建 `.nova/design/<date>_<topic>.md`，并在蓝图“待开发工作”中精确链接。
- 普通开发不创建设计文档。
- 待办实现完成后删除蓝图中的对应条目；保留设计文档，不记录 Review 状态。

## 实现与交付

1. 实现最小、完整、可验收的改动，保留用户无关工作树内容。
2. 运行与风险相称的测试和静态检查；失败则修复，同一问题连续三次仍无法解决时停止并报告。
3. 检查 diff，使用 Conventional Commit 创建一个内聚的本地提交。不要添加 Nova 编号或 trailers。
4. 不自动启动 Review，不 push、不发布。
5. 完成报告只列实际结果、关键文件、验证结果、提交和遗留风险；不生成或校验临时报告。
