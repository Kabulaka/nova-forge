# Nova 人工 Review

未收到用户明确 Review 指令时不得运行本流程。

## 范围

优先使用用户指定的 Git SHA、SHA range、分支差异或工作树范围。范围不明确且不同选择会改变审查对象时，只问一个范围问题。固定范围后不因发现相邻改动而扩围。

## 流程

每轮执行：

1. 主代理先核对 diff、需求边界和已有测试证据。
2. 委托独立 reviewer 只读审查固定范围，按严重程度报告可复现、可定位的问题；风格偏好不算缺陷。
3. 主代理统一核实问题，修复确认缺陷并运行相关测试。
4. 由 reviewer 对修正后的同一范围复审。

最多三轮。通过即结束；第三轮仍有阻断问题时停止并报告剩余问题，不得伪造 PASS。

## 提交与报告

- 有修正且复审通过时，创建普通 Conventional Commit；仅在安全且不会改写已共享历史时才 amend。
- 没有修正时不创建空提交。
- 不生成审计、manifest、工作项编号、closure transaction、Review 状态或 Nova trailers。
- 不修改蓝图来记录 Review，不自动 push 或发布。
- 报告审查范围、结论、发现与修复、测试、提交和遗留风险；不运行报告校验器。
