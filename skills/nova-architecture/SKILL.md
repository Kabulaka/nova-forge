# Nova 架构

用最少文档建立足以指导开发的公共技术边界。

## 执行

1. 先读取蓝图及与请求直接相关的精确架构链接，再通过定向搜索定位入口、代表性代码和配置；只有蓝图缺失或证据不足时才逐步扩大调查范围，禁止全仓内容读取。
2. 只有影响技术栈、模块职责、数据所有权、公共接口或运行形态且无法从现状判断时才澄清；一次只问一个关键问题。
3. 蓝图不存在时，使用 [蓝图模板](assets/PROJECT_BLUEPRINT.template.md) 创建 `.nova/PROJECT_BLUEPRINT.md`。
4. 蓝图已存在时，只有用户本次主动调用本技能才修改架构；否则只读取并遵循。
5. 仅在共享约束无法由蓝图简洁表达时创建 `.nova/architecture/<topic>.md`，并从蓝图使用精确相对链接引用。不要创建索引、状态文件或空目录。
6. 不扫描 `.nova/design/`，不创建需求、台账、审计、检查点、Review 状态或专有编号。
7. 修改后运行与项目相称的验证，并创建普通 Conventional Commit；不得自动 Review、push 或发布。

## 交付标准

- 蓝图保持简短，事实优先，七章结构稳定。
- 架构文档只记录需要长期共享的决定、边界和约束，不记录访谈过程或开发流水。
- 完成报告只包含实际结果、关键文件、验证、提交和遗留风险，不运行报告校验器。
