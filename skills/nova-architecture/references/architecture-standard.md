# Nova 蓝图架构规范

## 1. 文档职责

`.nova/PROJECT_BLUEPRINT.md` 是所有开发会话共同读取的项目宪法，只保存需要长期共同遵守的稳定事实：项目结果、技术硬约束、代码落位、模块职责、跨模块契约、用户明确沉淀的未完成工作和架构文档导航。

以下内容不得在蓝图展开：

- 单个功能的页面、字段、局部流程、权限、失败分支和故事级验收；
- 具体函数、SQL、迁移步骤、运维命令和可从代码恢复的实现细节；
- 已完成工作、提交记录、Review 状态和历史过程说明。

当前实现事实以代码、测试、迁移和配置为准。局部功能目标只有用户明确要求设计时才进入 `.nova/design/*.md`。

## 2. 七章结构

以下一级章节名称和顺序固定：

1. 项目定位：对象、问题和成功结果；
2. 技术栈：当前事实或已确认硬约束及来源；
3. 代码结构：顶层目录、职责和代码落位；
4. 模块职责：模块所有权、对外边界和允许依赖；
5. 公共约束：全局契约、数据与资源不变量、运行恢复和开发决策边界；
6. 待开发工作：仅保存用户明确要求沉淀且尚未完成的设计链接；
7. 架构文档：详细共享契约的精确导航。

架构导航已经属于蓝图，不再创建 `ARCHITECTURE_CONTRACTS.md`、架构契约目录索引、门禁状态或确认批次。可选的 `.nova/SHARED_CAPABILITIES.md` 只路由已经实现并通过最低验收的共享代码，不是架构索引。

## 3. 代码、模块与依赖

- 代码结构只列稳定区域和落位规则，不复制完整文件树。
- 每个模块给出唯一职责、对外边界和允许依赖；模块自己的业务表、查询和 Repository 仍由模块所有。
- 公共层只承载连接、事务、迁移、恢复、鉴权等共享机制，不得吸收模块业务语义形成万能层。
- 所有新增代码必须能映射到既有目录和依赖方向；需要新增技术栈、层、共享依赖、数据所有权或公共契约时，必须由用户主动进入 Architecture 确认。

## 4. 公共契约

- 公共 HTTP API 使用 OpenAPI 3.0.x/3.1.x；异步事件使用 AsyncAPI 2.x/3.x；数据所有权、一致性、资源生命周期和失败恢复使用与项目匹配的表格或专项文档。
- Mock 与 fixture 必须引用被模拟的 API 或事件契约；其声明版本必须与契约的 `info.version` 一致。
- 一个公共事实只保留一个权威位置。蓝图给出摘要和精确链接，详细文件给出完整契约，不在两处重复定义。
- 没有 API、事件、Mock、缓存或消息队列需求时写“不适用”，不创建空目录和占位文件。
- 共享依赖优先通过所有权、版本化接口和 Mock 解耦；只有业务顺序不可消除时才保留串行依赖。

## 5. 详细架构文件

只有共享契约无法在蓝图中简洁表达时才创建 `.nova/architecture/<topic>.md`：

- 文件名使用稳定、可读的主题，不使用流程编号；
- 蓝图“架构文档”必须精确链接到文件并说明其职责；
- 文件只写长期共享的决定、接口、数据、事件、Mock、运行或恢复边界；
- 不建立额外索引，不记录访谈、提交、审计、Review 或迁移状态；
- 修改公共契约时同步更新蓝图摘要和直接受影响的精确链接。

## 6. 待开发工作

待开发工作不是自动生成的任务台账。只有用户明确要求设计、规划或沉淀待办时才添加：

- 条目使用可读名称、交付结果和 `.nova/design/` 精确章节链接；
- 不生成 FEAT、FIX、PATCH、MAINT 或其他专有编号；
- 不维护开发中、待 Review、Review 通过等状态；
- 工作完成后立即删除对应条目，设计文件保留；
- 后续候选若未获用户授权，不得自动写入待开发工作。

## 7. 共享能力复用目录

`.nova/SHARED_CAPABILITIES.md` 只登记已经实现并通过最低验收的共享能力及其源码位置和复用边界。目录缺失或没有命中不证明能力不存在，Development 仍须定向检查相关代码和测试。候选、设计和未完成入口不得登记；代码移动、废弃或边界变化时在同一任务更新，最后一项能力退役时删除该文件，不保留空目录。

共享能力目录不是架构契约或架构索引，不替代代码、测试和配置。若候选或实现要求新增技术栈、层、共享依赖、数据所有权或公共契约，仍须由用户主动进入 Architecture 确认。

## 8. 完成检查

- 七章完整且有序，内容职责不混淆；
- 技术栈、代码落位、模块职责、依赖方向和公共边界足以指导开发；
- 详细架构只通过蓝图精确链接读取，没有第二套索引；
- 没有扫描或罗列设计目录；
- 没有空目录、占位架构、工作项编号、流程状态、审计或 Review 状态；共享能力目录存在时只含已实现且通过最低验收的入口；
- 当前事实、公共约束与局部设计的权威边界清晰。
