# Nova 架构契约规范

## 1. 最小交付与零差量

`.nova/PROJECT_BLUEPRINT.md` 保存技术栈、代码结构、模块依赖、跨模块不变量和系统恢复边界；`.nova/architecture/ARCHITECTURE_CONTRACTS.md` 只保存并行门禁、详细契约索引和不可消除硬依赖。具体 API、数据、事件和 Mock 契约按需拆文件。

蓝图“分层与代码映射”是代码落位和依赖方向的公共权威；`architecture/foundation/` 细化共享运行环境、物理目录及允许/禁止依赖。模块自己的业务表结构、查询和 Repository 仍由模块所有，但必须落入蓝图规定的层和目录；共享数据基础设施只承载连接、事务、迁移、并发、恢复等公共机制，不得吸收模块业务语义形成万能数据层。

每次进入架构阶段先逐项判断共享工程骨架、数据所有权、公共 API、事件和 Mock 是否发生真实差量。五项均无差量时，只在阶段报告中列出判断依据，随后直接交付开发：不生成 `ARCH-*`、不修改架构文件、不创建提交，也不启动 Review。存在真实差量时才用 `new-architecture-id` 生成一个 `ARCH-*` checkpoint；ARCH 是架构阶段身份，不是 FEAT，不进入蓝图“交付工作项”。

不生成 ADR、技术选型报告、会议纪要、类图或可从代码恢复的实现说明。没有 API、事件或 Mock 需求时在门禁标记“不适用”，不创建对应空目录。

## 2. 契约格式

- 公共 HTTP API 使用 OpenAPI 3.0.x/3.1.x；异步事件使用 AsyncAPI 2.x/3.x；数据所有权和一致性使用数据契约模板；Mock 与 fixture 必须引用被模拟契约，且声明版本必须等于该契约的 `info.version`。
- 契约索引路径必须相对 `ARCHITECTURE_CONTRACTS.md`，不得逃出 `.nova/architecture/`，引用文件必须存在。
- 新架构状态只使用 `待确认 / 已确认 / 不适用`。schema 1 历史中的 `待Review / 已通过` 与 PEND Review 依据继续只读兼容，不得用于新的架构交付。需要项必须存在对应类型的索引契约，门禁状态由该类型全部契约的最低状态派生；不需要项不得保留对应契约。
- `已确认`的确认依据必须是规范 `ARCH-*`，不得手填批次名或 FEAT。ARCH commit 使用 `Nova-Schema: 2`、`Commit-Kind: architecture`、Architecture-Ref、Requirement-Ref 和 Validation，并以 `arch(architecture): 中文结果摘要` 提交。`--ready` 从 Git 重建 Architecture-Ref 唯一性、需求 checkpoint、索引行及其所确认的当前契约字节；工作树变化、未提交 ARCH、ARCH 后漂移或 schema 1 后续逃逸均不能解锁。schema 2 ARCH 可作为当前架构历史的可信重基线，重基线后的索引变化仍须由新的合法 ARCH 覆盖。
- 实际数据库迁移、共享类型、接口代码和工程骨架放项目源码目录，架构文档只定义跨开发者必须一致的边界。

## 3. 并行门禁

共享工程骨架和数据所有权始终需要；API、事件和 Mock 是否需要由需求实际边界决定。全部“需要=是”的门禁均已确认且有 ARCH 依据后，`--ready` 才能通过。

架构阶段必须优先用所有权、版本化接口和 Mock 消除依赖。硬依赖表只保留无法通过技术契约解除的业务顺序；没有硬依赖时写一行“无”，所有需求块标记并行。

架构阶段不创建开发工作项。真实共享差量以一个 ARCH checkpoint 保存；详细功能实现仍沿独立能力边界建立 FEAT，只服务单个 FEAT 的内部实现选择留在该 FEAT，不得被泛化为共享架构。不得因为需求、架构、编码、测试等流程阶段不同而拆分 FEAT。

## 4. 变更边界

单个功能不得静默改变共享架构契约。发现契约不足时暂停该功能并返回 `nova-architecture`；真实差量经用户确认并形成合法 ARCH 后，再使直接受影响的功能设计与测试证据失效并重新绑定。没有差量时不得为了表示“走过架构”修改文件。

`.nova/SHARED_CAPABILITIES.md` 只索引已经实现并通过最低验收的共享能力及其源码位置，不是架构契约，也不替代代码和测试。功能开发可在既有分层与共享代码区域内随已确认工作项登记或更新；若候选或实现要求新增技术栈、层、共享依赖、数据所有权或公共契约，必须先走架构确认。目录没有匹配项只表示未登记，仍须定向检查相关代码后才能决定新建；没有已实现能力时不创建空文件。

## 5. 校验

- 蓝图与架构索引结构严格、路径安全、引用存在；
- 门禁需要、索引契约、状态和可信 ARCH 依据相互一致；
- 工程骨架与数据契约结构完整；API/事件含 OpenAPI/AsyncAPI 根版本；Mock 是合法 JSON 并引用已索引契约及版本；
- `foundation / api / data / events / mocks` 中不得存在空目录或未索引文件；
- 共享能力目录存在时，表头、唯一能力名、仓库内源码位置和占位符检查通过；
- `--ready` 在任一需要项未确认时失败，在全部共享前置有可信 ARCH 证据时通过；历史 schema 1 PEND 只按原审计语义兼容读取。
