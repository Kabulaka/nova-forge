# 非专业用户蓝图访谈 SOP

本 SOP 在目标项目的新会话首次提问前，或会话未记录 SOP SHA-256、当前指纹与记录不同时完整读取。只有同一会话、同一项目且 SOP 指纹未变化时才复用。

## 1. 后台关系记录

用户按自己的思路描述，AI 在后台维护最小关系记录，不向前台倾倒表格。

| 字段 | 最小内容 |
|------|----------|
| 话题 | 稳定名称、用户原话、当前理解 |
| 事实 | 用户已确认、项目事实、外部事实、参考来源 |
| 关系 | 上游目标、关联话题、影响范围 |
| 边界 | 隐含排除、待确认差量 |
| 状态 | 当前、相邻、暂存、闭环、冲突 |
| 权威 | `stage`、`authorityState`、用户原话或项目/外部证据位置 |
| 投影 | `stageProjection`：`inheritedContracts`、`stageEvidence`、`stageDecisions`、`unresolvedDeltas`、`resolutionBasis` |
| 委托 | `delegatedScope`、已披露的 `disclosedDecision` 及直接依赖 |
| 交付 | `activeDeliverySlice`：活动工作项、分类确定的工作包/里程碑值、验收范围、下一可执行动作与暂存范围 |
| 确认 | 覆盖整份摘要的 `finalConfirmation` 或待确认状态 |

保持追溯：`目标 → 用户场景 → 功能簇 → 行为契约 → 验收标准`。缺少上游目标的功能应被质疑，缺少验收的关键契约不能闭环。

后台同时维护固定收敛矩阵：访谈范围、目标、参与者、触发、正常结果、状态变化、权限、关键边界、失败恢复、共享复用、明确不做、验收证据。每格只允许“用户已确认 / 证据已查明 / 明确不适用 / AI 候选决定 / 待确认”并记录用户原话、项目事实或可定位外部证据；未枚举、无证据或仍为推断的格子一律按待确认处理，不得通过省略字段得到空差量。前台不逐格审批，最终只展示由矩阵生成的一份整设计摘要。

- **当前**：正在讨论的唯一主线。
- **相邻**：会改变当前含义，可能需要立即确认。
- **暂存**：已经记录，但现在展开会打断思路。
- **闭环**：体验、边界、失败和验收已确认；只有新信息影响时重开。
- **冲突**：前后表达不能同时成立，必须由用户选择。

会话内同时保留最小决策胶囊：稳定话题名、当前阶段、用户已确认内容、项目事实、外部事实、AI 候选决定、委托边界、未决差量、当前问题、直接依赖，以及实施交接有效时的 `activeDeliverySlice` 和暂存范围。上下文压缩或续接先恢复这些权威状态；缺少具体冲突时不得把已回答事项重置为待确认，也不得把暂存范围提升为当前范围。胶囊只是会话内恢复语义，不新增项目文件或宿主持久化。
`stageProjection` 只是当前权威状态的可重建分组，不产生新事实、决定或确认；进入任一阶段、合并答案、完成研究、修正候选、恢复上下文或形成最终摘要时均从同一快照重建。`inheritedContracts` 仅保存相关上游已确认契约的引用、来源阶段和证据位置，不得复制为本阶段决定或改写确认状态；`stageEvidence` 仅保存本阶段查明事实及证据位置；`stageDecisions` 仅保存本阶段新增且已完整披露的 AI 候选；`unresolvedDeltas` 仅保存会改变本阶段结果且无法由确认、证据、委托或明确不适用消解的差量并与实际数量一致；`resolutionBasis` 引用具体消解依据且在差量为零时也不得省略，不得用“无需讨论”等无来源结论替代。用户可见总结或整份摘要必须分开标明“继承契约”“本阶段查明事实”“本阶段新增 AI 候选决定”和“本阶段未决差量”；差量为零时显式写“本阶段未决差量：0”并列出 `resolutionBasis`，零差量不等于零研究、零候选或零工作，不得制造形式性问题，最终确认仍覆盖整份候选契约。本阶段证据与继承契约冲突时立即暂停当前及下游收敛，不改写为本阶段决定；按 `inheritedContracts` 来源返回需求或架构阶段，展示冲突证据并完成来源阶段整份重新确认，然后只失效并重建受影响投影，无冲突继承项保持有效且不得重问。
## 2. 选择一个差量

依次考虑认知连续性、影响范围、不确定性、不可逆性和可回答性。能由代码研究解决、影响小、可逆或纯内部实现的问题不占用提问预算。

每轮最多一个问题，只对应一个待确认差量。两个答案需要组合时也必须分轮，先问更不可逆、影响范围更大的一项。未问差量会改变当前理解时放入相邻分支，否则暂存。

### 访谈范围闸门

当前阶段为需求访谈，且属于绿地项目、总体需求首次访谈或用户明确重置项目范围时，第一问先确认 `MVP / 完整系统 / 自定义范围`：MVP 只覆盖最小可用业务闭环，完整系统覆盖当前目标所需的完整闭环和必要边界，自定义范围由用户指定阶段、对象或能力。后续差量、明确不做和验收都受该范围约束。已有项目的增量需求复用已确认范围，不得机械重问；只有范围证据缺失、冲突或用户要求重置时才重新确认。架构和开发访谈继承需求范围，只确认本阶段差量。

### 实施阶段范围闸门
实施交接激活后，以 `activeDeliverySlice` 而不是总体产品流程或蓝图全部待办计算当前差量。当前交付切片始终由活动工作项、验收范围和下一可执行动作限定；`PEND-*` 使用正式工作包及已有里程碑，`FIX-*`/`MAINT-*` 的工作包和里程碑固定为 `none`，不得为其创建或虚构治理实体。完成数据库、适配器、接口、测试或其他技术子步骤不等于当前工作项闭环，不得因此切换话题或恢复总体访谈。
一个差量只有同时满足以下条件才具备当前提问资格：属于当前交付切片；会改变当前功能行为、外部契约、安全边界或数据语义；直接阻塞下一可执行动作；无法由代码、配置、测试、既有确认、指定证据或当前委托消解。后续工作项、后续里程碑、只影响未来实现或总体流程但不阻塞当前动作的差量全部进入暂存范围，不得进入当前问题队列、候选收敛或“下一问”计算。当前工作项按既定完成门禁闭环且下一工作项经明确路由后，相关暂存范围才可激活。

| 实施状态 | 输入场景 | 唯一动作 |
|----------|----------|----------|
| 实施中 | 当前切片存在不可消解的阻塞差量 | `ask-current` |
| 实施中 | 技术子步骤完成且无当前阻塞 | `execute-next` |
| 实施中 | 出现后续工作项或里程碑差量 | `park-and-execute` |
| 实施中 | 用户委托按行业通用做法处理 | `resolve-current-only` |
| 实施中 | 用户指出跑偏或要求按既定顺序 | `correct-and-execute` |
| 已闭环 | 下一工作项已经明确路由 | `activate-next-slice` |
“按行业通用做法处理”等委托只消解当前被问差量和当前交付切片内的直接依赖，不授权生成、研究或询问后续阶段。用户指出跑偏、要求先完成当前阶段或按既定顺序推进时，视为范围纠偏中断：立即记录明确排除，移出越界问题，恢复并执行当前下一可执行动作；不得再询问是否返回当前阶段、是否继续或是否重新确认既有范围。无法恢复活动工作项或下一可执行动作时停止并报告缺失证据，不得用未来问题补位。
### 单问题闸门

发送前必须全部满足：

1. 可先用一句陈述解释为何需要答案，但陈述本身不要求作答。
2. 只有一个需要用户回答的句子，最多一个问号。
3. 只收集一个信息维度，不含“谁使用并如何完成”“分别说明”“同时确认”等复合任务。
4. 示例只解释当前维度，不形成第二个问题或流程清单。
5. 2–3 个互斥选项只要求一次选择，用用户可感知结果解释取舍并明确推荐，不同时追问理由或下一项决定。
6. 用户若必须串联多个答案才能作答，继续拆分，只发优先级最高的一问。

### 耦合方案收敛

结合已确认交谈内容和必要证据形成候选方案时，先说明依据及证据强度，再给出具体推荐；推荐可以包含多个明确列出的边界，但必须说明各边界为何共同构成一个不可分的行为选择、用户可感知影响和不采用内容。用户对这一项方案的明确确认可以同时更新其包含的多个收敛矩阵格。彼此可独立改变、取舍不同或没有直接依赖的决定不得打包，仍按单问题闸门分轮确认；用户后续修正只重开目标边界及其直接依赖。

凡把做法称为成熟/最佳实践，或方案涉及安全、身份、公共契约等高风险边界，先按外部参考研究 SOP 取得证据；普通低风险项目内候选只标为 AI 候选，即使包含多个直接依赖且不可分的边界也不因此触发外部研究，但不得伪装成已验证事实。

### 共享能力机会闸门

沟通中主动判断当前能力是否已有实现，或是否因跨页面/模块复用概率、实现成本、安全和一致性而值得独立。先查共享能力目录，再定向查代码和测试；目录无记录不能直接断言不存在。已有能力只说明复用位置和边界；新增或扩展共享能力必须向用户披露当前需要、可能复用场景、收益、本次成本与影响和明确建议，并只确认“共享建设 / 局部实现 / 局部实现但保留抽象边界”一个决定。用户确认前不得扩大范围、创建共享实现或登记目录；普通辅助代码、一次性布局和业务专属规则不得以想象中的复用为由触发。

### 委托决定闭环

1. 用户把一个范围明确委托给 AI 时，记录 `delegatedScope`，从提问队列移除其中可由 AI 决定的逐项参数；委托不外推到其他阶段、业务目标、公共契约或显著风险。
2. 委托命中外部参考研究 SOP 的显式或高风险触发时先研究；普通低风险内部实现可直接形成候选。委托只能免除形式性提问，不能免除必要研究、具体决定披露、用户修正机会和整份确认。
3. 每组候选决定在进入最终摘要前一次性披露：委托范围、具体决定、依据及证据强度、用户可感知影响、不采用内容和证据缺口。用户不必逐项批准，但可随时修正；沉默或普通“继续”不把候选变成正式契约。
4. 用户修正时只替换目标候选并重新计算直接依赖；无关已确认事实和无冲突候选保持有效。候选全部披露且其他差量清空后，才进入整份摘要确认。

### 阶段总结与交互载体

方案选择、冲突选择、写入确认或话题闭环时，先用普通回复给出短阶段总结，再提出当前唯一问题。阶段总结与话题闭环都必须从 `stageProjection` 生成并保留四个明确分组；阶段总结可将每组精简为当前相关项和必要推荐理由，但不得省略分组或把本阶段事实、候选排除在外，总结本身不要求作答。话题闭环使用覆盖整份候选设计的最终摘要，不按契约逐条要求确认。

1. 当前差量存在 2–3 个真实、互斥且可解释取舍的方案，并且宿主实际暴露原生结构化提问工具时，优先使用该工具；推荐项排第一。
2. Codex 使用当前可用的 `request_user_input`，Claude Code 使用当前可用的 `AskUserQuestion`；只依据本轮工具能力判断，不根据宿主名称、模式名称或配置文件猜测。
3. 不得为了显示选项自行切换 Plan mode、调用 `EnterPlanMode`，也不得修改宿主全局配置；模式和功能开关由用户控制。
4. 开放式事实问题、无法形成诚实互斥选项或原生工具不可用时，继续使用普通文本提出一个问题。
5. 原生工具只承载问题和选项；普通回复不得重复同一问题。工具是否已呈现无法确认时停止，不再追加文本问题。

### 答案后的统一推进
普通文本回复与原生工具返回的有效答案共用以下状态机；载体只决定问题如何呈现，不改变确认、继续或收敛语义。“每轮最多一个问题”约束每个交互步，不是整个 AI 执行周期只能提问一次。
存在有效实施交接时，先执行“实施阶段范围闸门”：答案只更新当前交付切片内的权威状态，越界内容进入暂存范围；当前没有具备提问资格的阻塞差量时，直接执行下一可执行动作，不进入下面面向访谈收敛的穷举提问循环。
1. 把答案及备注或自由补充并入对应权威状态；委托只记录为授权范围，不能直接标成已确认要求。最新明确补充覆盖默认含义，存在不能直接消解的冲突时只保留一个冲突差量。
2. 每次合并后重新计算当前话题的待确认差量和研究任务，并从更新后的权威状态重建 `stageProjection`，但只有符合当前阶段范围闸门的事项才能进入计算结果；不沿用回答前预判的“下一步”或“已收敛”。
3. 有代码、配置、测试或指定来源可查的研究任务时先研究；本轮能完成就研究后再次执行本状态机，不能完成才标记为“证据不足”并说明原因后停止，不把研究任务改问用户。
4. 访谈阶段有待确认差量时选择优先级最高的一项，按上一节载体规则立即提出一个问题；实施阶段只有具备当前提问资格的阻塞差量才适用本条。不得只列出待办、只说“建议下一步”或要求用户再次发出“继续讨论”。
5. 只有待确认差量和研究任务均为空，且目标、参与者、触发、正常结果、状态变化、权限、关键边界、失败恢复、共享复用、明确不做与验收证据的每格均处于“用户已确认 / 证据已查明 / 明确不适用 / 已完整披露的 AI 候选决定”之一、不得含“待确认”，才可形成“候选收敛”；局部流程明确但条件未满足时只能称“阶段结论”。AI 不得仅凭本项成立自行宣称已收敛。
6. 候选收敛后，展示覆盖整份设计的最终摘要，其中保留已披露候选决定及证据边界，并只询问“确认整份设计”或“继续调整”。只有用户对该摘要作出明确确认才进入已收敛；普通“继续”、要求开发、沉默、空答案、取消、部分答案及对其他问题的回答都不算确认。用户继续调整时合并新差量并回到第 2 条。确认后可自动生成设计并进入既定实施交接，不再询问是否开始编码。
7. 用户询问“还有要讨论的吗”或等价问题时，先执行本状态机；有剩余事项就直接研究或提出一个问题，没有也只能进入第 6 条的整份设计确认，不能由 AI 代答确认。
8. 只有当前话题已按第 6 条明确确认、用户要求暂停、继续前必须写入、研究暂时无法完成、工具失败或呈现状态不明时才停止；必须等待本次答案返回后再决定下一问，不得预先提交、并发提问或重复刚回答的问题。

### 结构化问题的中断与恢复

1. 工具因宿主超时、用户取消或其他未提交状态返回空答案、`0/1 answered` 时，视为当前问题未回答的非终态：不合并、不推进、不自动重试；原样保留问题原文、选项顺序、标签和说明，只说明尚未收到选择并等待用户继续。
2. 超时长度由宿主决定，本技能不写死、不延长也不轮询工具；用户明确继续时用原生工具原样重放该问题，工具不可用时用普通文本完整列出原选项。用户直接回复完整选项标签时可接受，但不得用缺少标签的 A/B/C 代替选项。
3. 正常连续访谈在最终确认前不写设计草稿。用户暂停或准备跨会话时，只询问一次是否保存；同意后才把当前全部未决差量写入“澄清中”设计，拒绝或未回答时不写文件。
4. 上下文压缩或恢复后先重建最小决策胶囊，再计算差量；能恢复已回答状态时直接继续剩余差量，只有发现具体冲突或确实无法恢复某一项时才说明原因并重开该项，不得从头重放访谈。

错误：

> 你的主要用户是谁，他们会怎样完成一次典型协作？

正确：

> 我先确认服务对象，因为这会影响后续协作和权限。
>
> 这个平台第一批主要给哪一类人使用？

## 3. 输出净化闸门

所有用户可见回复，包括摘要和交付说明，在发送前执行：

1. 只保留理解结论或回答当前问题所需的内容。
2. 子代理、工具和后台记录只作事实来源，必须重新组织，不能拼接原始输出。
3. 删除推理草稿、候选问题、规则自检、内部等级、代理名称/状态、工具过程和面向 AI 的提示。
4. 删除孤立人名、无上下文英文、调试标记和 `[one question]` 等流程标签。
5. 用户要求分析内部原文时才可展示，并明确标为被分析内容。
6. 无法判断内容是否面向用户时不发送；净化后为空就停止，不用内部状态补位。

错误：

```text
管理驾驶舱是否需要导出 Excel 报表？ [one question]
Larsen.
Could ask export, user. good.
```

正确：

```text
管理驾驶舱是否需要导出 Excel 报表？
```

## 4. 分支、闭环与冲突

用户谈 A 时涉及 B：先记录 B；B 会改变 A 当前含义且通过当前阶段范围闸门时只问一个最小差量，再回到 A；否则暂存。实施交接有效时，后续工作项或里程碑中的 B 即使重要也不得提前激活。回到 B 时复述已知结论，只问剩余差量，不从头询问。

围绕当前功能簇逐轮覆盖：为什么需要、谁使用、何时触发、正常结果、状态变化、权限、关键边界、失败与恢复、明确不做、验收证据。分类只在后台使用，不按章节审问用户。

只有“答案后的统一推进”允许闭环时，才可用短摘要确认；同一轮不要再开启下一话题：

> 到这里我理解的是：……，并且明确不做……。这段理解准确吗？

发现冲突时指出两种行为产生差异的具体场景，只问用户最终希望哪一种。新决定覆盖旧推断后，沿关系检查功能、权限、数据、架构和验收。

## 5. 外部参考

用户显式引用成熟平台、标准、最佳实践、产品或仓库，把安全、身份、公共契约等高风险事项委托给 AI，或 AI 准备把某项做法作为已验证的成熟/最佳实践提出时，按 `reference-research-sop.md` 研究。外部事实记为“证据已查明”，适配结果记为“AI 候选决定”；只有整份摘要明确确认后才进入正式契约。产品名仅作为当次证据源或解释示例时，不得固化为产品专属规则或自动纳入其全部功能。

## 6. 架构与开发边界

需求基本收敛后，必须澄清代码结构、系统分层及其目录映射；其他架构决策先解释用户可感知的成本、离线/多设备、隐私位置、故障恢复和扩展边界，不让用户在未知后果下选择框架、数据库或协议。

最终冻结五类边界：

| 边界 | 判定 |
|------|------|
| 本期必须实现 | 缺少即无法完成核心场景或验收 |
| 明确不做 | 容易被顺手扩展但未获授权 |
| 后续候选 | 当前不实施，只保留已确认兼容空间 |
| AI 可自行决定 | 不改变体验、外部契约、安全或数据语义的内部实现 |
| 必须再次确认 | 范围扩大、安全或外部契约变化、不可逆数据操作、新依赖/基础设施或显著成本 |

边界总结使用用户理解的能力名称，不用类名、表名或目录代替。仍有未决项时继续遵守单问题闸门。

## 7. 禁止行为

- 按蓝图章节逐项审问，或在一轮合并多个答复任务。
- 为了完整询问可从代码查明的事实。
- 用户体验未确认就锁定技术方案。
- 遗忘暂存分支，或重新询问已确认内容。
- 只记录正常功能，不记录排除、失败恢复和验收。
- 只读 README 或产品首页就声称完成参考研究。
- 把参考行为直接写成本项目要求。
- 向用户转发代理输出、工具日志或内部自检。
