# 外部参考项目研究 SOP

## 1. 触发与范围

满足任一条件时进入研究，并记录触发原因、当前阶段、委托范围和希望解决的决策：

- 用户显式引用成熟平台、标准、最佳实践、产品或仓库，或明确要求参考、类似、借鉴、照着某份文档或 URL；
- 用户把安全、身份、公共契约等高风险事项委托给 AI，即使没有指定参考对象，也必须先选择可定位的权威资料研究；
- 普通低风险内部实现既未指定参考对象也不涉及高风险边界时不强制研究。

- 只给出项目名或“做得像某项目”时，先用一个问题确认最想参考的体验或功能簇。
- 已给出明确功能时直接研究，不要求用户描述可从公开来源查明的事实。
- 产品名仅作为研究能力的例子、类比或历史说明，而不是当前项目要求时，不启动该产品的专属研究；继续按当前委托的通用范围判断。
- 高风险委托未指定对象时，AI 按当前阶段选择最少且足以决策的官方标准、监管资料或成熟产品公开契约，并在结果中披露选择依据；不得让用户代替检索。
- 参考对象只是证据来源，不代表用户授权复制全部功能、代码、界面或资产。

## 2. 子代理分工

范围明确且环境提供子代理时，至少启动一个只读探索子代理：

| 范围 | 分工 |
|------|------|
| 一个项目、一个明确功能 | 1 个代理追踪完整行为链 |
| 同一功能同时需要产品体验和实现契约 | 2 个代理分别研究用户行为与代码/API/状态 |
| 多个参考项目 | 按项目拆分 2–3 个代理并行研究 |

- 每个代理必须有互不重叠的对象、功能或证据维度；不得让多个代理重复泛读同一仓库。
- 主代理提供参考对象、版本或 URL、功能范围、必答问题和只读约束，不泄露预期结论。
- 主代理等待全部研究代理到达终态后再综合；中间消息、超时或空响应不能作为研究结论。
- 环境没有子代理时由主代理执行相同研究契约，并在反馈中说明未经过独立探索。
- 每个研究代理默认总时限为 20 分钟，单次外部命令或网络调用最长 120 秒；项目或用户给出更严格限制时从其限制。
- 等待调用超时只表示本次轮询结束。总时限内继续等待；达到总时限时由主代理中断其负责的研究代理，并将未返回部分标为证据不足。

建议的代理任务应包含：

```text
只读研究 <对象/版本> 的 <功能>。从入口追踪到状态、权限、失败和测试，返回证据位置、可迁移行为、不适合照搬的约束及未验证事项。不得修改文件，不得只总结 README。
```

## 3. 探索深度

开源代码项目先用 README 或文档定位，再检查实际实现。与当前功能有关时，追踪：

```text
用户入口 → 页面或命令 → API/事件 → 领域状态 → 权限 → 持久化 → 失败恢复 → 测试
```

- 不相关的层可以省略，但必须说明为什么不影响当前结论。
- 关键结论至少由两类证据交叉支持，例如实现与测试、官方文档与代码、API 契约与状态模型。
- 记录仓库 URL、分支、tag 或 commit、研究日期和许可证；行号可能漂移时同时记录文件与符号。
- 闭源产品只能使用官方帮助、API 文档、更新日志和可验证界面行为；不得声称已验证内部实现。

研究达到以下条件才可结束：

- 能说明谁在什么场景触发该功能；
- 能说明正常流程、关键状态和权限；
- 能说明主要失败、恢复和明确边界；
- 能指出可迁移能力、不适合照搬之处和可执行验收；
- 每项关键说法有证据，或明确标为未验证。

## 4. 证据包

每个代理一次性返回：

1. 参考对象、范围、版本和许可证；
2. 用户流程、状态、权限、失败与恢复；
3. 文件、符号、路由、测试或官方资料位置；
4. 可迁移的行为与适用条件；
5. 不适合照搬的约束和原因；
6. 证据冲突、访问限制和未验证事项。

事实与建议必须分开。没有证据的位置不得用常识补齐。

## 5. 综合与确认

主代理去重并交叉核对证据，先分离“外部事实”和“本项目 AI 候选决定”，只向用户展示：

- **参考事实**：参考对象实际怎样工作及证据强度，每个核心结论附至少一个可定位的关键证据，同类证据合并而不倾倒完整证据包；
- **具体候选决定**：在用户委托和当前阶段边界内选择的具体规则、默认值或行为，以及选择依据和用户可感知影响；
- **不建议照搬**：与当前范围、成本、安全或数据语义冲突的部分；
- **证据边界**：未验证、冲突或只可观察而无法证明内部实现的内容；
- **待确认**：只有仍存在不能由委托和证据消解、且会改变本项目结果的一个差量时才提问。否则把候选并入统一访谈的整份摘要，不要求逐项批准。

委托不等于确认。研究完成后必须按统一访谈 SOP 披露委托范围、具体候选决定、依据、影响、不采用内容和证据缺口；用户修正只失效目标候选及其直接依赖，普通“继续”或沉默不能把候选写成正式契约。

## 6. 失败、资源与许可证

- 仓库不可访问、版本不明或资料互相冲突时，报告证据边界并标记待确认，不伪造结论。
- 单个代理失败时，仅在剩余总时限足够时由主代理按相同范围重试一次或接管；仍无充分证据则停止推断。
- 用户取消研究时，主代理立即中断其负责的研究代理和外部调用，清理临时检出；取消、超时和预算耗尽均不得视为成功或完整证据。
- 达到时间、上下文或工具预算时，只能报告已经验证的事实及缺口；依赖缺失证据的适配建议必须撤回并标为证据不足。
- 外部访问保持只读；临时检出使用受限临时目录，完成后清理，不写参考仓库或用户项目。
- 不在提示、日志或报告中暴露凭据、私有源码和受限数据。
- 许可证缺失、不明或不兼容时，只提炼可观察行为和契约，使用 clean-room 方式独立设计；不得复制代码、文本、图标、布局资产或独特视觉表达。
