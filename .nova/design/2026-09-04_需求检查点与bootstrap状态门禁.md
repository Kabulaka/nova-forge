## WP-01 需求基线与可控任务交付

### 契约

| 契约 | 维度 | 语义键 | 唯一规则 |
|------|------|--------|----------|
| WP-01-C01 | 交付边界 | WP-01/范围 | 本期实现 requirement 与 delivery-plan 检查点、严格交付台账、可控任务拆分、内部里程碑、计划变化、Review 聚合、五项进度查询以及需求/架构/开发/Review 技能流程；不实现自动 Review、push、SVN 或团队项目管理集成。 |
| WP-01-C02 | 参与者与权限 | WP-01/授权 | 只有用户明确确认整份需求且需求索引与需求块校验通过后，需求技能才可创建精确范围本地 requirement commit；该提交不进入人工 Review，远程写入仍须独立授权。 |
| WP-01-C03 | 触发与输入 | WP-01/输入 | 输入必须是同一仓库当前已确认并提交的 `REQ-...@vN`、必要架构证据、完整任务候选、蓝图投影及可隔离 Git 基线；当前 bootstrap 将三个未归档开发 PEND 收敛到 `PEND-01a06a50-27d0-7fe5-8d30-ab9de658eaa0`。 |
| WP-01-C04 | 结果、状态与不变量 | WP-01/检查点身份 | requirement commit 必须携带 `Nova-Schema`、`Commit-Kind: requirement`、`Requirement-Ref`、`Requirement-Path`、`Requirement-SHA256` 和 `Validation`，且只包含该需求块、索引及其直接需要的总体业务段落；不得携带 Work-Item、设计或 Review trailers。 |
| WP-01-C05 | 结果、状态与不变量 | WP-01/索引状态 | 需求索引接受“待实现、开发中、已实现、已更新”；开发中时“已实现版本”和“实现依据”必须同时为“无”或同时指向上一完整实现，不能把当前未完成版本写成已实现。 |
| WP-01-C06 | 结果、状态与不变量 | WP-01/任务边界 | 新 PEND 必须有独立完整结果与验收，并可独立排期、暂停、恢复、Review 或取消；流程阶段、文件、模块、技能、代理和提交批次不能成为拆项依据，只有共同完成才有价值的步骤保留为同一 PEND 的内部里程碑。 |
| WP-01-C07 | 结果、状态与不变量 | WP-01/台账 | delivery-plan commit 绑定需求检查点和计划版本；严格 JSON 以 `work_items` 保存独立 PEND、依赖、完成定义、设计引用和状态，以 `milestones` 保存任务内部切片、状态和提交证据，所有变化递增版本且不得物理删除历史身份。 |
| WP-01-C08 | 结果、状态与不变量 | WP-01/Review与聚合 | requirement/delivery-plan commit 不进入 Review；一个 PEND 的所有实现提交统一选择，只有整体完成定义满足后才进入一次人工 Review；PASS 原子关闭工作项、更新台账和蓝图，全部有效 PEND PASS 后才把需求置为已实现。 |
| WP-01-C09 | 结果、状态与不变量 | WP-01/进度 | 查询按精确 Requirement-Ref 或活动 Work-Item 定位，固定返回 total、completed、current、remaining、blocked，并在 current 中展示内部里程碑完成、当前、剩余和阻塞；结果只从提交、台账、蓝图和可信审计派生。 |
| WP-01-C10 | 失败与恢复 | WP-01/失败封闭 | 元数据混用、过度拆分、路径越界、指纹失配、台账非法、依赖成环、历史删除、审计伪造、staged diff 夹带或 Git 基线漂移时拒绝动作，不创建部分提交或部分状态，并保留上一有效投影。 |
| WP-01-C11 | AI 决策边界 | WP-01/实现决定 | 可在 Python 标准库、既有需求校验器和 Review 原子写入口内选择最小结构并补齐测试；改变任务独立性标准、用户权限、需求状态、Review 授权、依赖/网络或远程写入必须再次确认。 |

### 验收

| 覆盖契约 | 场景 | 预期结果 |
|----------|------|----------|
| S-01、WP-01-C01、WP-01-C02、WP-01-C03、WP-01-C04 | 确认并校验一个新需求后立即停止，不进入架构或开发 | 形成只含允许文件的独立 requirement commit，可从 trailers、commit 和需求块字节恢复 Requirement-Ref、路径与 SHA-256。 |
| WP-01-C04、WP-01-C10 | 分别提交字段混用、错误路径、错误 SHA-256、未确认需求及夹带无关文件的候选 | 每个候选均失败且不产生 commit，原工作树和暂存区保持可恢复。 |
| WP-01-C05 | 校验待实现、开发中无历史实现、开发中保留上一实现、已实现和已更新的索引，并构造字段冲突反例 | 合法组合 PASS；当前版本伪装已实现、单边“无”和非法状态均 FAIL。 |
| WP-01-C03、WP-01-C06、WP-01-C07 | 将当前检查点、台账和技能流程三个 PEND 候选按边界复核并迁移 bootstrap | 只保留一个活动 PEND，三个交付步骤成为有状态内部里程碑；delivery-plan 绑定 v2 检查点且蓝图只有一行。 |
| WP-01-C06、WP-01-C07 | 分别输入一个含三个独立能力的大需求和一个由三个流程步骤组成的小修改 | 前者可形成三个 PEND；后者因独立性不成立只能形成一个 PEND 和三个里程碑，过度拆分候选失败。 |
| WP-01-C07、WP-01-C09、WP-01-C10 | 创建、激活、提交 Review、阻塞、恢复和查询台账，并构造非法状态、成环、删除历史与 Git 漂移 | 合法转换逐版留痕并稳定输出任务与里程碑进度；非法候选零写入且继续返回上一有效状态。 |
| WP-01-C08 | 在历史中混合 requirement、delivery-plan、work-item 与 audit commit 后选择并 PASS 当前 PEND | 只选择当前 PEND 的全部 required 提交；检查点不进入 Review；PASS 原子更新台账、蓝图、设计、审计和需求终态。 |
| WP-01-C08、WP-01-C11 | 执行既有无台账工作项关闭、需求状态和提交契约回归测试 | 历史 Work-Item 与审计行为兼容，无新增第三方依赖，也不自动启动 Review、push 或 SVN。 |
