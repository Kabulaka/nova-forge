## WP-01 交付治理分类与报告闭环

### 契约

| 契约 | 维度 | 语义键 | 唯一规则 |
|------|------|--------|----------|
| WP-01-C01 | 交付边界 | WP-01/范围 | 同一工作项交付编号、分类、蓝图投影、需求链接、阶段报告、提交首行、Review 闭环、Doctor 诊断和正反用例；不自动 Review、push、SVN，不增加远程状态、任务模板文件或业务语义判定状态机。 |
| WP-01-C02 | 参与者与权限 | WP-01/授权 | 用户确认需求和架构方案后可执行实现与精确本地提交；Review 仍只由用户明确启动，REJECT 修正属于已授权 Review 范围，远程写入始终单独授权。 |
| WP-01-C03 | 触发与输入 | WP-01/分类 | 新能力用 FEAT，主动局部调整用 PATCH，有既有契约偏离证据的恢复用 FIX，非产品能力维护用 MAINT；新入口禁止 PEND，schema 1 历史 PEND 保持可读。 |
| WP-01-C04 | 结果、状态与不变量 | WP-01/架构 | 进入架构先判断五类共享边界；零差量不创建 ARCH、文件、提交或 Review，真实差量才形成不进入交付工作项表的 ARCH checkpoint。 |
| WP-01-C05 | 结果、状态与不变量 | WP-01/蓝图 | 蓝图交付工作项只投影 FEAT 与历史 PEND，状态只用待澄清、待开发、待Review；设计依据和依赖不得用无上下文待澄清，Requirement-Ref 必须是可校验链接。 |
| WP-01-C06 | 结果、状态与不变量 | WP-01/提交 | schema 2 首行固定 type(scope): 中文结果摘要；scope 来自稳定白名单；一个工作项默认一个结果 commit，仅预先登记且有独立恢复价值的内部里程碑允许同编号追加提交。 |
| WP-01-C07 | 结果、状态与不变量 | WP-01/Review | 开发提交只标记未 Review/待Review；REJECT 轮次不提交，最终 PASS 只产生一个同时包含全部 Review 修正、审计和投影关闭的 closure commit，审计以修正摘要避开自身 commit 哈希循环。 |
| WP-01-C08 | 结果、状态与不变量 | WP-01/报告 | 需求、架构、FEAT、PATCH、FIX、MAINT、Review 各有阶段专用固定结构；首段必须说明实际结果和明确未改范围，再列依据、验证、提交、Review、遗留和下一步。 |
| WP-01-C09 | 失败与恢复 | WP-01/失败封闭 | 编号、分类、首行、scope、trailers、蓝图状态、引用、报告字段、提交数量、Review 修正摘要或审计不一致时脚本与 Doctor FAIL，保持上一可信状态且不创建部分提交。 |
| WP-01-C10 | AI 决策边界 | WP-01/语义边界 | 脚本验证结构、映射、引用、历史和摘要，不冒充工作项独立性、PATCH/FIX 业务事实或架构合理性判断；真实需求/架构冲突返回权威阶段，局部实现歧义在当前开发澄清中尽量闭环。 |

### 验收

| 覆盖契约 | 场景 | 预期结果 |
|----------|------|----------|
| S-01、WP-01-C01、WP-01-C02、WP-01-C03、WP-01-C06 | 分别生成并验证 feature、patch、fix、maintenance，读取历史 PEND，再提交宽泛 scope、英文摘要和新 PEND 反例 | 新任务得到 FEAT/PATCH/FIX/MAINT 与中文首行；本期不触发自动 Review 或远程写入；历史可读；所有逃逸反例 FAIL。 |
| WP-01-C04 | 分别处理无共享差量和改变数据所有权的需求 | 前者零产物进入开发；后者形成可信 ARCH，且蓝图交付工作项中无 ARCH。 |
| WP-01-C05 | 蓝图登记待澄清、待开发、待Review FEAT，并构造裸待澄清依赖、纯文本需求编号和第四状态 | 三个合法状态及链接 PASS；歧义、不可点击引用和额外状态 FAIL。 |
| WP-01-C06 | 对同一 FEAT 按文件拆三次提交，再按一个结果提交；另以两个预登记可恢复里程碑追加提交 | 碎片提交拒绝；单结果提交通过；只有真实里程碑例外通过且保持同一 FEAT。 |
| WP-01-C07 | 对一个 FEAT 执行两轮 REJECT 修正后最终 PASS | REJECT 零 commit；最终仅一个 closure commit，修正、审计、台账与蓝图原子一致且可查询。 |
| WP-01-C08 | 分别生成七类完成报告并删除实际结果、未改范围、Review 对象或下一步字段 | 完整报告按阶段通过；任一必填字段缺失时验证失败。 |
| WP-01-C09、WP-01-C10 | Doctor 扫描 schema 混用、ARCH 伪造、新 PEND、蓝图/台账偏移、待Review 缺失和多次 Review 提交 | 每项给出稳定 PASS/WARN/FAIL 与证据；只读执行，不修改项目，也不把语义判断伪装成自动结论。 |
