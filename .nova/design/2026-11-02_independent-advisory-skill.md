# 独立顾问技能设计

> 演进来源：无。
> 项目依据：[项目蓝图](../PROJECT_BLUEPRINT.md)、[双宿主插件边界](../architecture/foundation/dual-host-plugin.md)。

<a id="design-summary"></a>
## 1. 目标与成功结果

| 问题 | 成功结果 |
|------|----------|
| 主任务中的既有方案、推断和历史叙述可能影响后续分析 | 用户可显式调用独立顾问，由全新上下文的子代理研究问题并提供第三方意见 |
| 需要针对具体难点灵活使用思考方法 | 顾问选择能改变当前判断的分析动作，提供有依据的候选方案、取舍和验证建议 |
| 通用方法和固定流程可能增加无效工作 | 一次咨询默认只使用一名顾问，内容按问题裁剪，现有技能继续承担方案决策 |

## 2. 范围与项目依据

- 包含：新增候选名称为 `nova-consult` 的独立咨询技能，随 Nova Forge 分发；显式调用、隔离委托、只读调查、方法选用、参数选择、咨询结果和失败处理构成同一交付。
- 明确不包含：接入默认开发流程、增加现有技能的必读依赖或自动调用、代替现有技能决策、实施修改、执行实验、正式代码 Review、递归委派、多顾问并行、持久化咨询状态或报告文件。
- 实现资源以一份简短 `SKILL.md` 和必要的宿主调用策略元数据为主；本次不引入运行服务、新 SDK、调度器、参数配置中心或方法注册表。
- 模型与思考度的用户指定值可在每次显式咨询时调整，适用条件见第 3.2 节。

当前项目事实：

- 蓝图第二至第五章限定现有五个技能，新增项目级技能属于 Architecture。本设计保存拟新增能力的功能契约；实现前需由 Architecture 处理最小骨架差量。本次设计写入只同步蓝图第七章，不改变系统骨架。
- 两个插件 manifest 均使用 `skills: "./skills/"`，`package.json` 将整个 `skills/` 目录纳入发布资源。DSH 通过已有适配入口挂载共享资源。
- [插件校验](../../scripts/validate-plugin.mjs)、[包内容检查](../../scripts/check-package.mjs)、[开发安装](../../scripts/codex-dev-plugin-lib.mjs)和[结构测试](../../tests/plugin-structure.test.mjs)含固定技能集合；实现时需要同步相应集合与必要资源断言。
- [Review 第三章](../../skills/nova-review/SKILL.md)已有独立代理、显式思考度及宿主原生工具的规则。其思考度策略作为本设计第 3.2 节的依据；显式模型选择是本能力新增的要求。咨询运行时不要求加载 Review 技能。

## 3. 行为与契约

| 契约 | 维度 | 唯一规则 |
|------|------|----------|
| C-01 | 触发 | 只有用户显式点名 `nova-consult` 或对应宿主的显式技能入口才发起咨询。普通分析、开发、设计或建议请求继续使用既有路由。 |
| C-02 | 参与者与权限 | 主代理组织委托并呈现咨询结果；顾问只提供分析、候选方案、条件性建议及验证建议。方案采纳、取舍与任务推进由当前任务所在的既有技能处理，用户决策边界继续有效。 |
| C-03 | 输入与隔离 | 委托使用第 3.2 节的隔离参数，输入只保留咨询问题、目标、用户确认的硬约束、必要原始证据或精确入口、允许调查范围。用户确认、已核实事实、主代理候选和未知分别标明；候选方案可按咨询目标提供，不复制完整父会话或将主代理结论冒充事实。 |
| C-04 | 调查与副作用 | 顾问可在委托范围内独立只读核实事实，并遵守目标项目规则；无证据时保留不确定性。顾问不修改文件、配置、蓝图或外部状态，不执行实验、开发测试或长时间计算，不再创建子代理。 |
| C-05 | 分析方法 | 按第 3.1 节选择能缩小当前关键判断缺口的方法，并落实到具体对象、动作和判断依据；不按任务名称或复杂程度固定遍历方法。 |
| C-06 | 结果 | 用与问题相称的自然语言给出候选与取舍、关键依据、影响结论的假设或缺口、必要的验证建议；按实际需要取用这些内容，无固定方案数量或报告模板。事实、建议和计划中的验证保持可区分，未执行实验不得写成已验证结论。 |
| C-07 | 生命周期 | 每次显式调用默认新建一名顾问。主代理可向同一顾问补充当前缺口所需的原始信息，不固定多轮，不自动扩展咨询范围。结束或取消时沿用宿主原生代理生命周期，不增加持久状态。 |
| C-08 | 失败与恢复 | 输入不足、隔离或参数不可用、证据不足、代理失败与取消按第 3.3 节处理；没有取得完整结果时明确说明咨询未完成。 |
| C-09 | 分发与兼容 | Codex、Claude Code 与 DSH 共享同一份技能正文；使用各宿主原生子代理能力和已有 provider，字段映射见第 3.2 节。必要的显式调用策略由宿主原生元数据与技能入口共同表达，现有五个技能、全局规则与 Hook 不增加顾问调用或依赖。 |

### 3.1 方法选择

选择依据是当前最影响判断的缺口。顾问自行选择分析手段，C-02 规定的方案决策权保持不变。

| 当前判断缺口 | 方法 | 实际动作与适用限制 |
|--------------|------|--------------------|
| 某个未经证实的前提可能改变问题定义或方案选择 | 第一性原理 | 从目标、基本事实和硬约束重新推导，核实该前提及原有机制的必要性；用户已确认的目标和约束继续有效。 |
| 一项具体主张、方案或关键假设需要经受反例检验 | 对抗性审查 | 寻找能推翻主张的反例、失败条件或证据，说明它如何影响建议；没有发现反例不等于证明正确，普通边界检查也无需贴此标签。 |
| 多项改动共同影响同一指标，需要区分贡献 | 消融实验 | 设计基线、指标、控制变量及启用或移除组合，必要时考虑相互作用和测量波动；只分析已有结果或提供实验建议，执行权限遵守 C-04。 |
| 多个方案满足相同目标，需要判断额外机制是否值得 | 奥卡姆剃刀 | 比较假设、组件、运行和维护成本，使额外复杂度对应实际收益；代码行数或修改量不能单独代表整体复杂度。 |
| 职责混杂、共同变化或依赖牵连需要明确边界 | 高内聚、低耦合 | 根据共同变化、数据与资源所有权、稳定契约分析职责和依赖方向，提出边界及影响范围建议；不为使用该方法强加抽象层。 |

普通事实核实或直接分析已经足够时直接完成。每种被采用的方法都应能说明它改变了哪项调查、方案比较或验证建议；证据变化后可切换或组合方法。用户指定方法时优先按该方法研究；必要条件尚未满足时，核实条件或说明限制，不虚构前提与结果。输出遵守 C-06，无需额外逐项汇报方法匹配过程。

### 3.2 子代理选择与参数

主代理在创建顾问时明确选择参数。取值来自用户输入或宿主明确暴露的会话配置和能力，不能靠模型猜测。宿主工具与字段名可以不同，下列语义保持一致：

| 参数 | 选择规则 |
|------|----------|
| 模型 `model` | 用户本次指定优先，否则使用主代理当前实际模型；创建调用中显式传入选定模型，不硬编码品牌、版本或不同模型作为隐式替代。 |
| provider | 使用与所选模型匹配且宿主已注册的 provider；宿主有独立字段时明确选择，不新增注册或修改全局设置。 |
| 思考度 `reasoning_effort` | 显式传入；用户指定优先，否则默认与主代理当前思考度一致。仅在咨询范围明确且风险集中时可提高一个所选模型支持的相邻档位，并说明具体理由；已在最高档时保持。 |
| 上下文 | 全新上下文；Codex 使用 `fork_turns: "none"`，其他宿主使用能确认具有相同隔离语义的原生能力。输入内容受 C-03 约束。 |
| 代理角色 | 使用宿主适合通用分析的角色，并在委托中明确 C-02、C-04 的咨询职责和只读权限；角色不改变权限或决策归属。 |
| 调查范围 | 明确目标项目和允许访问的证据入口；宿主支持工具权限限制时同步配置只读边界，其他工具使用仍受 C-04 约束。 |

更高思考度不能替代缩小无关上下文或补充必要事实。宿主只允许省略参数并静默继承、无法可靠取得选定值、模型或档位不可用、无法确认全新上下文时，统一按第 3.3 节的能力或参数缺口处理。

### 3.3 失败与恢复

| 情况 | 处理 |
|------|------|
| 无法从请求或当前已知信息确定咨询问题 | 主代理只澄清一个会改变咨询内容的具体差量，取得足够输入后再委托；不让用户填写固定表单。 |
| 必要模型、思考度或其他参数无法确定，或宿主不支持所选值 | 明确指出缺失或不支持的参数，暂停当次委托；可从可信信息恢复时先恢复，否则只询问所需差量，不猜测、不静默更换取值。 |
| 宿主无法创建独立代理或保证全新上下文 | 报告该宿主当前无法完成独立咨询及具体原因，交回当前任务；不以主代理分析替代已完成的第三方意见。 |
| 证据不足或允许范围内无法取得事实 | 返回已核实依据、未知及条件性建议；无法形成有依据的建议时明确证据不足，并给出最小核实路径。 |
| 代理报错、空结果、仅有中间消息或无完整结果 | 说明咨询未完成，保留已取得且可核实的信息，不作完成声明，不启动固定重试循环。 |
| 仅等待窗口结束，代理仍在运行 | 继续按宿主原生等待能力等待；单次等待超时不代表咨询失败或完成。 |
| 用户取消或要求停止 | 中止当前咨询并按宿主能力终止尚在运行的顾问；保留用户已确认的目标和约束，不自动开启下一次咨询。 |
| 需要写入、实验、最终拍板，或顾问发生越权写入 | 顾问返回相应建议或权限缺口，由既有技能处理。实际越权写入使本次只读咨询失效，主代理报告已知影响，不把该结果当有效独立咨询，也不擅自回退用户内容。 |

## 4. 流程、复用与实施边界

一次咨询由主代理依据 C-01 接收显式请求，按 C-03 和第 3.2 节组织最少必要输入与参数，委托顾问依 C-04、C-05 调查分析，再按 C-06 呈现意见。意见回到当前任务后按 C-02 处理。异常直接使用第 3.3 节，不增加其他阶段或状态记录。

复用现有 `skills/` 分发方式、宿主原生代理能力和既有检查工具。Review 只作为参数及独立只读原则的设计依据，不引入其七维检查、问题分级、复审轮次或正式结论机制。

实现预计涉及：

- 新增 `skills/nova-consult/SKILL.md` 和必要的宿主调用策略元数据。
- 在已有插件校验、包内容检查、开发安装和相关测试中纳入新技能；只调整实际受影响的入口，不另建分发框架。
- 在使用说明中增加独立显式入口；保持默认流程、现有技能正文、全局规则与 Hook 的咨询调用行为符合 C-09。
- 先按项目规则完成新增项目级技能所需的最小架构调整；该动作不属于本次文档写入。

AI 可自行决定不改变上述语义的措辞、内容组织、内部标识和宿主字段映射。多顾问并行、增加其他方法体系、改变模型默认策略或顾问权限、接入既有流程、新依赖和显著成本变化均不在本次交付内，需要重新确认。

## 5. 验收

| 覆盖契约 | 场景 | 预期结果 |
|----------|------|----------|
| C-01、C-09 | 执行普通开发或设计请求，未显式调用顾问 | 原有路由继续工作，不创建咨询子代理，不增加顾问必读依赖 |
| C-01、C-02、C-06 | 显式咨询一个存在多个可行方案的问题 | 提供候选、取舍依据和条件性建议，方案采纳与推进仍由既有技能处理 |
| C-03、第 3.2 节 | 父会话包含无证据的偏好结论及与当前问题无关的历史内容 | 实际委托为全新上下文；输入保留必要事实，偏好如被提供则标为候选，无关历史不进入委托 |
| C-03、C-04 | 提供准确代码入口及一项待核实主张 | 顾问可定向只读核实，并区分主代理推断与查明事实；工作副本及外部状态不发生修改 |
| C-05 | 简单问题只需核实一个明确事实 | 直接完成必要分析，不固定遍历五种方法或生成方法匹配报告 |
| C-05、C-06 | 请求检验一项具体主张，或分析职责混杂、方案复杂度 | 对相应对象给出反例检验或边界、成本比较；方法产生具体分析依据，而非只出现名称 |
| C-04、C-05、C-06 | 缓存与批处理共同改善指标，输入没有分项实验结果 | 给出控制变量与必要组合的实验建议，不执行实验，不虚构各项贡献或测试通过 |
| C-05、第 3.3 节 | 用户指定方法，但适用条件或关键证据缺失 | 定向核实条件或说明限制，保留事实与假设边界，不强加前提 |
| 第 3.2 节 | 用户未指定模型和思考度，宿主已可靠暴露主代理取值 | 实际创建调用显式携带相同模型与思考度，并使用已注册 provider 和全新上下文 |
| 第 3.2 节 | 用户指定受支持模型和思考度；另测范围明确且风险集中的咨询 | 用户指定值优先；未指定时仅按规则提高一个受支持档位，并说明理由 |
| C-08、第 3.3 节 | 模型值未知、参数不支持、隔离不可用 | 明确指出具体缺口，不猜测、不静默替换、不伪装独立咨询完成 |
| C-07、C-08、第 3.3 节 | 代理报错、返回空结果、仅等待超时，或用户取消 | 分别执行对应处理，不将等待超时当终态，不把不完整结果当完整咨询，不自动扩展代理或范围 |
| C-02、C-04、C-08 | 咨询要求附带直接修改或拍板；另测顾问越权写入 | 执行与决策交回既有技能；实际越权使本次咨询失效，报告影响且不擅自回退 |
| C-09 | 安装与打包后在各宿主验证显式入口 | 新技能资源完整，原有技能继续可用；无法满足必要代理或参数能力的宿主按缺口处理，不降低契约 |

实现后的验证复用现有插件结构、开发安装与包内容检查，并在隔离测试环境观察实际代理创建参数、输出和副作用。结构检查只证明加载与分发，行为场景需由实际委托验证；不以关键词或标题出现代替验收。本次只写入设计，以上场景尚未执行。
