## WP-01 插件状态自动初始化与迁移

### 契约

| 契约 | 维度 | 语义键 | 唯一规则 |
|------|------|--------|----------|
| WP-01-C01 | 交付边界 | 状态初始化/范围 | 本期在共享 core 实现状态根解析、幂等 bootstrap、宿主隔离迁移，接入 Hook、MCP、兼容安装器、manifest/打包校验、README 和自动化测试；不新增网络、数据库、原生依赖、状态清理入口、发布动作或跨会话/宿主同步，不以本地测试替代双宿主真实 E2E |
| WP-01-C02 | 参与者与权限 | 状态初始化/权限 | 默认状态根为当前用户主目录下 `.nova`，唯一覆盖变量 `NOVA_HOME` 的非空值必须是规范化绝对路径；安装器只尽力预建，Hook 的首次 `SessionStart` 与 MCP 返回 `initialize` 前必须自行补建并验证，卸载、禁用和缓存清理均不获得删除状态授权 |
| WP-01-C03 | 触发与输入 | 状态初始化/输入 | Hook 与 MCP 从可信宿主环境识别 `codex` 或 `claude-code`，将 `PLUGIN_DATA`、`CLAUDE_PLUGIN_DATA` 或兼容的 `NOVA_PLUGIN_DATA` 仅作为同宿主旧数据来源；不接受相对 `NOVA_HOME`，不把插件根、工作区或系统临时目录作为候选权威根 |
| WP-01-C04 | 结果、状态与不变量 | 状态初始化/布局 | 权威检查点固定落于 `NOVA_HOME/state/{host}/{scopeKey}`，rendezvous 固定落于 `NOVA_HOME/rendezvous/{host}`，迁移记录按宿主隔离；bootstrap 通过创建、写入、同步、原子替换和删除同根临时探针证明持续可写，重复调用不得改变有效状态 |
| WP-01-C05 | 结果、状态与不变量 | 状态初始化/迁移 | 迁移仅枚举当前宿主旧根中的 `state/{host}/{scopeKey}`，逐个校验 envelope 的 schema、校验和、host、scopeKey 与 cwdHash；在新根暂存、同步、校验后原子提交宿主迁移记录才切换权威，rendezvous、锁、能力文件、配额临时状态和原始会话 ID 一律不迁移，旧根永不删除或覆盖 |
| WP-01-C06 | 失败与恢复 | 状态初始化/失败 | 根路径无法解析、相对覆盖、权限不足、探针失败、损坏旧状态、中断或目标存在不同有效状态时失败封闭；错误必须包含规范化目标或来源路径及设置绝对 `NOVA_HOME` 的恢复方向，不得静默回退工作区、插件缓存或 `/tmp`，未提交迁移内容不得成为可读权威 |
| WP-01-C07 | 失败与恢复 | 状态初始化/并发 | bootstrap 与迁移使用用户根内按宿主隔离的所有者锁和幂等记录；双宿主或同宿主多进程并发不得互读、双写或覆盖未知目标，已完成的等价复制可幂等复用，中断重试从最后已提交迁移记录继续 |
| WP-01-C08 | AI 决策边界 | 状态初始化/决策 | AI 可决定标准库模块拆分、探针文件名、迁移记录内部字段及测试夹具组织；改变 `~/.nova` 默认值、`NOVA_HOME` 唯一覆盖、宿主物理隔离、非破坏迁移、失败封闭、卸载保留或引入依赖/网络/真实发布必须再次确认 |

| WP-01-C01、WP-01-C08 | 执行运行时、Hook、MCP、兼容安装器、manifest、打包和 README 校验，并检查卸载/禁用路径 | 包中包含新的共享 core，双 manifest 不再把插件缓存声明为权威数据根；卸载和禁用不删除 `NOVA_HOME`，无清理、发布、网络、数据库或原生依赖扩张 |
