## WP-01 Windows 原生审计关闭

### 契约

| 契约 | 维度 | 语义键 | 唯一规则 |
|------|------|--------|----------|
| WP-01-C01 | 交付边界 | Windows关闭/范围 | 本期交付平台无关的 manifest、审计与查询核心，以及 POSIX/Windows 锁、路径和发布适配；覆盖 `check-manifest`、`record-pass`、`query` 及 Doctor、Architecture、Requirements、Delivery 的关联读取，不依赖 WSL；基础承诺限原生 Windows、NTFS、Python 3 与 Git for Windows，SMB、ReFS 和同步盘不在本期承诺内 |
| WP-01-C02 | 参与者与权限 | Windows关闭/授权 | 只有既有 Review 流程已明确授权且 manifest 通过校验时才能执行关闭；跨平台改造不得扩大自动 Review、远程写入或 Git 提交权限 |
| WP-01-C03 | 触发与输入 | Windows关闭/输入 | 同一 CLI 接受仓库路径和 manifest 路径，必须正确处理 Windows 分隔符、中文和空格路径；仓库、临时文件、日志、标记和目标必须位于同一仓库卷内 |
| WP-01-C04 | 结果、状态与不变量 | Windows关闭/事务状态 | 持久事务阶段固定为 `PREPARED`、`APPLYING`、`COMMITTED`、`CLEANED`；每次阶段转换先持久化日志，再执行该阶段允许的幂等动作，唯一逻辑提交标记定义整组关闭对 Nova 读取方可见 |
| WP-01-C05 | 结果、状态与不变量 | Windows关闭/读取一致性 | Nova 的 `query`、选择和关联校验读取审计状态前必须检查关闭事务；未完成事务只能在持锁恢复后读取，无法恢复时失败封闭，不得返回部分关闭 |
| WP-01-C06 | 结果、状态与不变量 | Windows关闭/路径安全 | 每个输出路径保持仓库内约束、拒绝任一现有祖先或最终组件为 symlink 或 Windows reparse point，并拒绝跨卷发布；平台能力不足以证明安全时失败封闭 |
| WP-01-C07 | 失败与恢复 | Windows关闭/普通失败 | 普通写入、替换或校验失败必须在持锁状态下恢复关闭前字节、清理本事务临时资源并返回非零；不能证明已恢复时保留日志并阻止后续读取 |
| WP-01-C08 | 失败与恢复 | Windows关闭/中断恢复 | 进程在任一事务阶段终止后，下一次关闭或审计读取必须基于持久日志和内容摘要幂等回滚或前滚；重复恢复与重复 `record-pass` 不得新增或重复审计记录 |
| WP-01-C09 | 失败与恢复 | Windows关闭/并发 | 仓库级跨进程排他锁覆盖校验、发布与恢复；锁竞争遵守确定性超时，异常进程退出后锁由操作系统释放，竞态不得覆盖未知的新内容 |
| WP-01-C10 | AI 决策边界 | Windows关闭/决策 | AI 可决定标准库内的平台适配类名、事务日志内部 JSON 字段和测试夹具组织；改变 CLI、审计 schema、事务阶段、逻辑可见性、基础文件系统承诺或引入第三方依赖必须再次确认 |

### 验收

| 覆盖契约 | 场景 | 预期结果 |
|----------|------|----------|
| S-01、WP-01-C01、WP-01-C02、WP-01-C03 | 在原生 Windows 的中文空格路径仓库执行 `check-manifest → record-pass → closure commit → query`，并运行 Doctor、Architecture、Requirements、Delivery 关联流程 | 全部命令使用本机 Python 与 Git 成功，输出和生成的审计字节满足既有跨平台契约，无 WSL 或第三方依赖 |
| WP-01-C04、WP-01-C05、WP-01-C08 | 分别在 `PREPARED`、`APPLYING`、`COMMITTED`、`CLEANED` 阶段注入进程终止，再连续执行两次查询或关闭 | 第一次先恢复到唯一一致状态，第二次结果幂等；任一不可恢复状态均返回非零且不暴露部分关闭 |
| WP-01-C06 | 将输出最终组件及逐级祖先替换为 symlink、Windows junction 或其他 reparse point，并构造跨卷临时/目标路径 | 所有危险路径在写入前失败封闭，外部目标和既有仓库字节不变 |
| WP-01-C07、WP-01-C08 | 在各发布步骤注入创建、同步、替换和清理失败，并强杀发布进程后重启 | 普通失败零污染；中断保留可恢复证据，重启恢复后无临时未知文件、重复记录或漂移投影 |
| WP-01-C09 | 两个进程并发关闭同一仓库，覆盖锁等待、超时、正常释放和持锁进程强杀 | 同时最多一个发布者进入事务；等待者确定性成功或超时，强杀后可重新获取且状态可恢复 |
| WP-01-C10 | 在 Linux、macOS、Windows CI 分别运行 Nova 五技能治理测试和 Review 端到端用例 | 三平台公共断言一致，POSIX 既有历史兼容与失败语义无回归 |
