# Nova Development 纯开销优化设计

> 演进来源：无
> 项目依据：[项目蓝图](../PROJECT_BLUEPRINT.md)中的低干扰开发辅助 SOP 定位、按需加载技能边界和现有插件验证入口

<a id="nova-development-overhead-optimization"></a>
## 1. 目标与成功结果

| 问题 | 成功结果 |
|------|----------|
| 受控 5×5 Plain/Nova 完整开发对照中，Nova 两轮总耗时成对中位数增加 14.9%、原始 token 增加 25.5%、有效 token 增加 52.2%，且个别 Nova 样本出现重复验证导致命令数达到 24 | 在不删除正常代码搜索、构建、测试和真实验收的前提下，消除相关内容与环境未变化时重复执行已通过命令的行为，并以同口径配对实验判断修改是否降低 Nova 的实际增量 |

性能目标中的“总耗时增量约不高于 10%、有效 token 增量约不高于 30%”只作为后续优化方向，不是本次单点修改的硬验收值。本次必须先证明重复验证被消除且质量不退化；不能把两个不同任务的会话总量相除作为 Nova 开销。

## 2. 范围

- 包含：调整 `skills/nova-development/SKILL.md` 的验证批次表述，使禁止重复执行未失效的已通过命令成为该批次首要约束；在 `tests/plugin-structure.test.mjs` 增加对应契约断言；完成仓库验证和临时隔离 5×5 Plain/Nova 配对实验。
- 明确不包含：修改 `codex/AGENTS.global.md`、其他技能、项目架构、默认模型或 reasoning；减少任务所需的代码搜索、构建、测试或真实验收；引入持久缓存、状态机、台账、命令编排器或长期 benchmark 基础设施；Review、Commit、push 或发布。

## 3. 行为与契约

| 契约 | 维度 | 唯一规则 |
|------|------|----------|
| C-01 | 参与者与权限 | 用户决定是否实施和是否保留候选修改；Development 只能在本设计范围内调整技能与契约测试，不能借优化扩大全局规则或其他技能。 |
| C-02 | 触发与输入 | 只有相关代码、配置、测试、工具环境或验收要求发生变化，或者已有结果失败、不完整、覆盖不足、用户明确要求重跑时，才允许再次执行已经通过的验证命令。 |
| C-03 | 结果与不变量 | 禁止重复验证不得削弱正常开发工作：代码搜索、受影响测试、最终静态检查、任务 diff、状态核对和用户要求的真实验收仍按风险执行；同一命令因有效证据仍成立而省略时，必须复用原结果而不是宣称未执行的验证。 |
| C-04 | 接口与数据 | 本次只改变 Markdown 技能契约及其结构测试，不新增运行时接口、业务数据或持久状态；性能数据只来自临时隔离实验，不写入项目运行时。 |
| C-05 | 配对实验 | Plain 与 Nova 必须使用相同任务、初始代码、模型、provider、reasoning、认证副本、质量验收和交错顺序；首轮与续改均要求退出码为 0、usage 非空、行为与输入完整性验收通过，无效样本整对排除并补跑。 |
| C-06 | 保留与恢复 | 只有质量保持 10/10、Nova 轨迹中不存在无状态变化的重复成功命令，且两轮总耗时与有效 token 的成对中位数均不高于修改前基线时，才保留候选修改；任一条件不满足则撤回本次候选技能与测试差异，并报告证据，不放宽验收。原始 token 和命令数同时报告但不替代前述条件。 |
| C-07 | AI 决策边界 | AI 可以在不改变既有语义的前提下选择最短清晰措辞、组织临时实验和补跑无效配对；如需降低 reasoning、修改全局规则、增加永久 benchmark、改变测试范围或扩大到其他技能，必须重新取得用户确认。 |

## 4. 流程与复用

1. 在“高效执行”的验证批次首句明确：相关内容和环境未变化时，不得重复执行已经通过的命令；同步删除同一条中的同义尾句，避免为了去重反而增加固定文本。
2. 在现有 Development 结构契约测试中增加该规则的精确断言，不新建测试框架。
3. 依次执行 Development 技能校验、定向结构测试、项目完整检查、包内容检查和 `git diff --check`；失败后只修复失败项及其影响范围。
4. 使用临时隔离环境运行与基线一致的 5×5 首轮开发与同会话续改配对实验，记录首轮、续改和总计的耗时、原始 token、缓存输入、有效 token、命令数、退出状态与质量结果。
5. 按 C-06 决定保留或撤回候选实现。实验脚本和夹具不进入仓库；设计文件保留，实施并验收完成后删除蓝图中的待开发条目。

直接依赖和复用入口：

- `skills/nova-development/SKILL.md` 中现有“测试与证据复用”“高效执行”和“同任务续改”契约；
- `tests/plugin-structure.test.mjs` 的 Development 结构契约测试；
- `scripts/validate-plugin.mjs`、现有项目检查和包检查入口；
- 既有隔离 `CODEX_HOME` 的 Plain/Nova 配对方法，仅作为临时验收方法复用。

## 5. 验收

| 覆盖契约 | 场景 | 预期结果 |
|----------|------|----------|
| C-01、C-02、C-03 | 相关内容和环境未变化，前序验证命令已经通过 | Development 复用有效证据，不再次执行同一命令；最终报告准确引用已执行结果，不省略仍必要的最终验收。 |
| C-02、C-03 | 修改影响了代码、配置、测试或环境，或者已有验证失败、不完整 | 只重跑受影响验证；影响无法限定或验收明确要求全量时运行完整验证，不因优化规则跳过。 |
| C-04 | 检查仓库差异和插件包内容 | 只出现设计与蓝图记录，以及获准实施后的 Development 技能和结构测试差异；没有运行时状态、永久 benchmark 或额外治理文件。 |
| C-05 | 运行 5×5 Plain/Nova 首轮与续改配对 | 10/10 有效样本均通过行为、测试、输入完整性和未提交验收；无效样本不进入统计，并按相同编号整对补跑。 |
| C-02、C-05、C-06 | 检查 Nova 工具轨迹 | 没有在相关内容和环境未变化时重复执行已经通过的命令，命令长尾不再由重复验证造成。 |
| C-05、C-06 | 比较修改前后的成对中位数 | 质量保持 10/10，两轮总耗时和有效 token 均不高于基线；否则撤回候选技能与测试修改并保留失败分析。 |
| C-07 | 优化建议需要降低 reasoning、修改全局规则或加入持久机制 | 本次停止扩围，先向用户展示独立方案并取得明确确认。 |
