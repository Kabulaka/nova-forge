## 1. 共享约束

### 1.1 问题与成功结果

| 问题 | 成功结果 |
|------|----------|
| `nova-brainstorming` 对“首次创建某类文档”和历史设计取证的范围定义不明确，可能在已有文档体系的项目中加载跨业务完整示例、读取没有依赖的旁支设计，并把同一文件拆成多次固定窗口读取 | 文档资源由目标项目事实、直接关系和稳定指纹按需加载；成熟项目不读取无关示例，演进来源只做满足当前决策所需的最小取证，同一资源不产生无效重读，且不修改第三方插件或宿主展示 |

## WP-01 文档资源按需加载与去重

### 契约

| 契约 | 维度 | 已确认约束 |
|------|------|------------|
| WP-01-C01 | 交付边界 | 收紧 `nova-brainstorming` 中蓝图规范、设计规范、模板、完整示例和历史设计的加载条件，并以契约测试固定行为；不改变蓝图或设计格式，不修改插件、hook、宿主 UI 和其他技能 |
| WP-01-C02 | 参与者与权限 | Codex 只读访问当前任务必要的项目文档和技能资源；示例不得覆盖项目事实或扩大已确认范围，任何插件、权限或宿主行为变更均需用户另行确认 |
| WP-01-C03 | 触发与输入 | 创建或更新蓝图、设计时按目标项目绝对路径和文件事实路由：不存在 `PROJECT_BLUEPRINT.md` 且正在首次创建蓝图时才加载蓝图示例；`docs/design/` 不存在有效设计且正在首次创建设计时才加载关联设计示例；已有对应文档体系时只加载规范、模板和当前项目相关文档。确定演进来源时先从当前需求、蓝图引用和已确认关系锁定候选，再按 S-05 逐级取证 |
| WP-01-C04 | 结果、状态与不变量 | 同一会话、同一目标项目中，路径和 SHA-256 未变化的同一资源只完成一次逻辑读取并复用理解；不得以 `wc` 加固定行窗口反复读取，同一文件只有工具明确截断时才从未返回位置继续，且不得发起超过已知文件末尾的空读取。读取候选终态设计的元数据已经足以确认身份和状态时，不再展开正文 |
| WP-01-C05 | 失败与恢复 | 无法确认目标项目、文档是否存在、设计是否有效、演进候选或资源指纹时，不得把加载跨业务示例或遍历旁支设计当作兜底；先用文件名、蓝图链接和头部元数据缩小候选，仍有多个候选且选择会改变设计语义时停止并只确认该差量。资源读取截断时只补读缺失部分，指纹变化时废弃受影响理解并重读，连续变化无法取得稳定快照时停止并报告 |
| WP-01-C06 | AI 决策边界 | 可在宿主允许范围内选择一次读取、并行读取或批处理，并调整不改变语义的测试组织；可在元数据不足或存在冲突时定向补读相关契约，但不得自行扩展为完整历史设计或旁支设计扫描。改变示例适用范围、缓存隔离边界、完整读取语义，或触及插件、hook、UI 与权限时必须再次确认 |

### 验收

| 覆盖契约 | 场景 | 预期结果 |
|----------|------|----------|
| S-01、S-02、WP-01-C03 | 在已有版本 3 蓝图和有效设计的项目中新建设计 | 读取设计规范、模板和当前项目相关文档，不读取 `references/examples/equipment-borrowing/` 中的蓝图或关联设计 |
| S-01、S-02、WP-01-C03、WP-01-C04 | 在既无蓝图也无有效设计的绿地项目首次创建两类文档 | 仅加载与当前创建类型对应的规范、模板和完整示例，每个必要资源最多完成一次逻辑读取，示例内容不进入项目需求 |
| S-03、WP-01-C04 | 同一会话、同一项目连续更新文档且资源指纹未变化 | 后续轮次复用可信理解，不再次读取相同规范、模板或已加载示例 |
| S-03、WP-01-C04、WP-01-C05 | 已加载资源发生一次变化，或工具明确截断长文件 | 只失效并重读变化资源，或从截断位置补读缺失内容；不从头重放固定窗口，不产生越过文件末尾的空读取 |
| WP-01-C05 | 项目路径、文档存在性或指纹无法可靠取得 | 停止资源路由并报告一个明确阻断，不加载设备借用示例作为通用兜底，不绑定不稳定快照 |
| S-05、WP-01-C03、WP-01-C04 | 当前需求明确演进自一个终态设计，且其头部元数据可确认身份与状态 | 只读取候选设计头部元数据并建立演进链接，不展开其共享契约、工作包正文或其他历史设计 |
| S-05、WP-01-C03、WP-01-C04、WP-01-C06 | 元数据不足以证明覆盖关系，或当前要求与候选设计可能存在契约冲突 | 只定向读取相关共享契约、工作包及直接依赖；取得结论后停止，不继续扫描无关章节或旁支设计 |
| S-04、S-05、WP-01-C01、WP-01-C02、WP-01-C06 | 优化 `nova-brainstorming` 资源路由，用户已明确不修改插件，候选演进来源为 Nova 终态设计 | 读取 `Nova技能套件与人工Review工作流.md` 的必要元数据；不读取没有依赖的 `Context-mode可选路由治理.md`，也不修改插件、hook 或 UI |
| S-04、WP-01-C01、WP-01-C02、WP-01-C06 | 检查实现范围和工作区差异 | 变更仅涉及 `nova-brainstorming` 资源路由、对应测试及本工作项文档；context-mode 插件、缓存、hook、Codex UI、权限配置和其他技能保持未修改 |
