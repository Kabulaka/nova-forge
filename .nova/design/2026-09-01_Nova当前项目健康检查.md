## WP-01 当前项目健康检查

### 契约

| 契约 | 维度 | 语义键 | 唯一规则 |
|------|------|--------|----------|
| WP-01-C01 | 交付边界 | 健康检查/范围 | 本期交付技能入口、UI 元数据、只读诊断脚本、行为测试以及 README、全局路由和发现校验集成；脚本检查 `.nova` 布局、迁移需求、蓝图、需求、架构、共享能力、设计、审计和本地 Markdown 引用，明确不检查全局技能安装、技能源码更新或远端版本，也不执行修复或迁移 |
| WP-01-C02 | 参与者与权限 | 健康检查/权限 | 任意项目使用者可发起诊断，但该调用不产生 Git 写入、网络访问、安装、修复、迁移或其他状态变更授权 |
| WP-01-C03 | 触发与输入 | 健康检查/输入 | 脚本仅从当前工作目录通过 Git 确定项目根目录，不提供项目路径参数；非 Git 目录或外部项目参数必须拒绝 |
| WP-01-C04 | 结果、状态与不变量 | 健康检查/结果 | 每项输出 `PASS / WARN / FAIL` 并汇总；核心蓝图缺失、Schema 或引用不一致、审计不一致及适用校验器失败为 `FAIL`，明确存在迁移计划为 `WARN`，未建立可选层不失败；存在 `FAIL` 时进程返回非零 |
| WP-01-C05 | 失败与恢复 | 健康检查/失败 | 子校验器异常、超时、读取或解析失败必须以有界证据报告并保持项目原状；失败后只给出定向只读复查命令，不自动重试写操作、回滚或修复 |
| WP-01-C06 | AI 决策边界 | 健康检查/决策 | AI 可自行决定不改变状态语义的内部函数拆分、证据裁剪上限和测试组织；改变检查对象、状态判定、只读边界、依赖、网络或修复能力必须再次确认 |

### 验收

| 覆盖契约 | 场景 | 预期结果 |
|----------|------|----------|
| S-01、WP-01-C01、WP-01-C03、WP-01-C04 | 在当前 Nova Git 项目根目录执行诊断 | 聚合所有适用校验，当前项目逐项通过并输出总 `PASS`；不读取另一个项目或全局技能安装 |
| WP-01-C03、WP-01-C04 | 在非 Git 目录、缺少核心 `.nova` 数据的 Git 项目或传入外部项目参数执行 | 分别以 `FAIL` 或参数错误拒绝，进程返回非零且不转向其他目录 |
| WP-01-C01、WP-01-C04、WP-01-C05 | 项目存在迁移计划、坏 Markdown 引用、无效设计或不一致审计 | 分别输出 `WARN` 或 `FAIL` 和有界证据；代码示例中的伪链接不形成坏引用 |
| WP-01-C02、WP-01-C05 | 在有未提交文件的项目中执行并比较运行前后 Git 状态 | 运行前后状态逐字一致，脚本及其子进程不留下项目写入 |
| WP-01-C01、WP-01-C06 | 校验技能结构、发现入口并运行各技能回归 | `nova-doctor` 可发现，技能结构、专项行为和既有技能测试全部通过，且未引入第三方依赖 |
