## WP-01 需求基线与完整交付台账架构

### 契约

| 契约 | 维度 | 语义键 | 唯一规则 |
|------|------|--------|----------|
| WP-01-C01 | 交付边界 | WP-01/架构范围 | 新增交付治理工程骨架和需求交付台账数据契约，更新总体需求、架构索引和蓝图，并预登记三个后续开发 PEND；本工作包不实现技能或脚本。 |
| WP-01-C02 | 参与者与权限 | WP-01/确认与Review | 用户确认整份需求后授权独立 requirement 本地提交；需求与 delivery-plan 检查点不 Review，架构只在共享边界变化时进入且一旦进入必须 Review PASS；普通开发仍按 Work-Item 策略等待用户明确 Review。 |
| WP-01-C03 | 触发与输入 | WP-01/基线输入 | requirement 检查点输入只包含已确认且通过校验的当前需求版本及直接总体索引变化；输出 commit、逐字 Requirement-Ref、需求块路径和内容 SHA-256，下游必须四者一致。 |
| WP-01-C04 | 结果、状态与不变量 | WP-01/提交分型 | requirement、delivery-plan、work-item 和 audit 四种 commit kind 字段集合互斥；Review 发现只选择声明 required 的 PEND/FIX/MAINT，不把需求或计划检查点当作待审功能。 |
| WP-01-C05 | 结果、状态与不变量 | WP-01/完整台账 | 首个开发切片前，每个 REQ@版本恰有一个版本化严格 JSON 台账，一次性登记全部稳定 PEND、依赖、完成定义和 Requirement-Ref；后续详细设计可在逐项激活时补齐。 |
| WP-01-C06 | 结果、状态与不变量 | WP-01/状态聚合 | delivery-plan 检查点成功后需求进入开发中；单个 PEND PASS 只增加完成数，只有全部有效 PEND 均可信 PASS 且当前、剩余、阻塞为空时才转为已实现并保存全部依据。 |
| WP-01-C07 | 结果、状态与不变量 | WP-01/进度投影 | 蓝图投影全部未完成有效切片；任何入口都从台账和可信审计固定展示 total、completed、current、remaining、blocked，不从会话记忆补齐。 |
| WP-01-C08 | 失败与恢复 | WP-01/计划变化 | 切片新增、拆分、合并、替代、重排、取消或阻塞必须递增计划版本并保留原身份、关系和原因；不能证明业务验收不减时拒绝更新并返回需求阶段升级版本。 |
| WP-01-C09 | 失败与恢复 | WP-01/原子失败 | requirement 提交、架构 ready、台账、蓝图、审计或聚合任一失败时保持上一有效状态，不进入开发中、不激活切片、不产生部分 commit，也不宣称进度已保存。 |
| WP-01-C10 | AI 决策边界 | WP-01/可变边界 | AI 可决定不改变字段、状态、Review、安全或业务验收的内部函数名、测试夹具和展示措辞；改变 commit kind、台账权威、状态聚合、单当前切片、Review 门禁或范围减少规则必须再次确认。 |

### 验收

| 覆盖契约 | 场景 | 预期结果 |
|----------|------|----------|
| S-01、S-02、WP-01-C01 | 执行需求、设计、蓝图和架构普通校验并检查 diff | 新需求、两份架构契约、本设计及四个完整 PEND 登记相互一致；需求仍待实现，只有当前架构 PEND 有设计链接。 |
| S-03、WP-01-C01、WP-01-C02 | 检查文件列表、Git 与 Review 状态 | 只出现治理文档并形成一个合法 designed 本地 commit；未改技能/脚本/审计，未自动 Review、push 或远程写入。 |
| WP-01-C03、WP-01-C04 | 用候选 commit schema 评审 requirement、delivery-plan、work-item、audit 样例和非法混合样例 | 四类字段集合和选择逻辑确定；需求/计划检查点可作为下游基线但不进入 Review，非法混合失败封闭。 |
| WP-01-C05、WP-01-C07 | 用一个含三个切片的需求检查台账、蓝图和跨会话进度结果 | 首片开始前全部切片已持久化；详细设计未展开项仍有稳定身份；五项进度只由项目证据派生且顺序稳定。 |
| WP-01-C06 | 三个切片依次 Review PASS 并观察需求状态 | 前两次仍为开发中并保留剩余；第三次 PASS 后才已实现，全部实现依据可从可信审计验证。 |
| WP-01-C08 | 分别执行等价技术拆分和减少业务验收的计划变更 | 前者保留原身份、替代关系、原因并递增版本；后者失败并要求创建已重新确认的需求版本。 |
| WP-01-C09、WP-01-C10 | 模拟校验失败、并发漂移、审计缺失和越权改变 Review 门禁 | 均保持上一有效提交与状态，不产生部分投影；改变受保护架构语义必须重新确认。 |
