# 跨压缩任务状态恢复

> 需求块规范版本：1
> Requirement-Key：REQ-01a0621d-6904-7a4f-bd7e-4552e3c8f994
> 需求版本：v1
> 所属模块：会话连续性

## 1. 目标

| 业务问题 | 成功结果 |
|----------|----------|
| Codex 与 Claude Code 的长任务经过上下文压缩后可能遗漏用户决定、控制约束、当前范围或下一动作，恢复时反复加载完整技能和规范又持续消耗上下文 | 两个宿主通过同一份轻量全局规则提高压缩信息完整性，使普通任务和 Nova 流程能够沿用既有决定继续，未变化控制内容不重复全文加载 |

## 2. 参与者与业务流程

| 步骤 | 参与者 | 触发与输入 | 业务结果 |
|------|--------|------------|----------|
| 1. 安装规则 | 用户 | Nova Forge 工作区和两个宿主的用户级规则入口 | 一个安装脚本为 Codex 与 Claude Code 启用同一份全局规则，README 提供可核对的安装说明 |
| 2. 推进任务 | 用户与 AI | 用户目标、项目规则、回答、纠正、委托、证据和执行结果 | 当前上下文明确区分已确认、候选、排除、未决和下一动作 |
| 3. 压缩 | AI 宿主 | 当前会话达到自动或手工压缩条件 | 按全局规则优先保留继续任务必需的信息，并以引用和内容指纹代替重复保存完整技能、规范和模板 |
| 4. 恢复 | AI | 压缩摘要、当前会话记录和工作区事实 | 沿用原目标、范围、决定、证据和下一动作，不从头询问或无条件重载控制文档 |
| 5. 信息缺失 | AI 与用户 | 压缩摘要缺少会改变当前行为的信息 | 先用当前会话记录或工作区事实定向确认；仍无法确认时只询问缺失的具体决定 |

## 3. 业务规则

| 规则 | 唯一定义 |
|------|----------|
| R-01 | 首个版本同时支持 Codex 与 Claude Code，并对普通任务和 Nova 的需求、架构、开发、Review 流程采用同一套压缩保留语义。 |
| R-02 | 两个宿主复用同一份权威全局规则内容，不维护会随宿主分叉的重复规则副本。 |
| R-03 | 提供一个同时支持 Codex 与 Claude Code 的安装脚本，并由 README 说明两个宿主的安装、验证和冲突处理方式。 |
| R-04 | 安装目标已是软链接时，脚本只解除该链接并重新指向当前工作区的权威规则源，不删除链接指向的内容；目标为普通文件或真实目录时拒绝覆盖并明确报告。 |
| R-05 | 当前用户明确指令优先于项目规则，项目规则优先于全局默认工作约定；宿主自身不可覆盖的系统、安全和权限边界不属于本规则范围。 |
| R-06 | 压缩摘要应保留当前目标与阶段、用户已确认决定、明确排除、委托范围、已披露候选、未决差量、当前问题、活动交付范围、有效证据、文件与提交状态以及下一动作。 |
| R-07 | 已加载的技能、规范和模板应保留绝对路径与内容指纹；内容未变化时继续复用，不得为了保险重复全文加载。只有内容变化，或当前动作必须取得逐字内容而摘要未保留时，才精确读取受影响内容。 |
| R-08 | 压缩后应沿用已保留信息继续，不重新询问已有答案；只有缺失信息会改变当前行为且无法由当前会话记录或工作区事实确认时，才询问该项。 |
| R-09 | 新建会话不自动继承旧会话的未完成任务；没有旧会话记录或明确交接时不得声称能够恢复。 |
| R-10 | 密码、访问令牌和其他秘密不得进入压缩摘要、安装诊断或长期记忆。 |
| R-11 | 本能力属于提示约束下的尽力保证；验收验证保留效果和规则加载，不承诺宿主压缩绝不遗漏。 |

## 4. 边界与异常

| 场景 | 业务结果或恢复 |
|------|----------------|
| 安装目标是已存在的软链接 | 只解除链接本身并重新建立链接，不删除原链接目标。 |
| 安装目标是普通文件或真实目录 | 拒绝覆盖，报告准确目标并由用户自行决定如何处理。 |
| 压缩摘要包含未确认的 AI 候选 | 保持候选身份并保留证据边界，不得提升为用户已确认事实。 |
| 压缩摘要缺少用户原决定 | 定向检查当前会话记录和工作区事实；无法确认时只询问该决定。 |
| 控制内容的内容指纹发生变化 | 只失效受影响引用并取得新版本，不重载无关控制内容。 |
| 即将输出固定模板但摘要没有逐字正文 | 根据已保留路径精确取得对应模板后输出，不凭记忆简化。 |
| 同项目开启新的会话 | 作为新任务开始，不自动取得其他会话的未完成状态。 |
| 压缩内容疑似包含秘密 | 排除秘密原值，只保留继续任务所需的非秘密状态。 |
| 宿主未按提示保留某项内容 | 如实报告提示约束的能力边界，不伪造已恢复信息或虚报验收通过。 |

## 5. 独立交付边界

| 交付结果 | 共享业务输入输出 | 架构前置 | 硬依赖 | 明确不做 |
|----------|------------------|----------|--------|----------|
| 一名全栈工程师可交付两个宿主共用的压缩保留规则、安全安装脚本、README 安装说明和验收证据 | 输入为当前会话事实、工作区事实及宿主用户级规则入口；输出为两个宿主加载的同一规则内容和更完整的压缩摘要 | 需要确认两个宿主的用户级规则发现方式、软链接安全边界和可执行验收场景 | 无业务硬依赖 | Hook、数据库、恢复服务、项目状态文件、Claude 专用规则副本、新会话自动继承旧任务、跨设备同步、长期个人记忆、保存秘密、自动覆盖或合并已有普通规则文件、绝对不遗漏承诺 |

## 6. 验收

| 覆盖规则 | 场景 | 预期结果 |
|----------|------|----------|
| R-01 R-02 R-03 | 分别安装并启动 Codex 与 Claude Code | 两个宿主的用户级入口解析到同一份权威全局规则，README 的安装与验证步骤可执行。 |
| R-04 | 两个宿主的目标入口分别为已有软链接、普通文件和真实目录 | 已有软链接只被解除后重建且原目标内容保留；普通文件和真实目录均被拒绝覆盖并得到明确错误。 |
| R-05 | 当前用户或项目规则覆盖全局默认行为 | 任务按更高优先级规则执行，全局压缩规则不阻断用户的明确选择。 |
| R-06 R-11 | 普通任务和 Nova 任务压缩前包含已确认决定、排除项、候选、未决问题、证据、文件与提交状态和下一动作 | 压缩后检查各项是否保持身份和关系，并将未保留项如实计入结果，不以提示规则存在代替实际验收。 |
| R-07 | 同一版本技能和规范跨多轮及多次压缩继续使用 | 摘要保留绝对路径与内容指纹，恢复时不重复全文加载；指纹变化时只更新受影响项。 |
| R-08 | 压缩摘要缺少一个已回答且会改变行为的决定 | 先用当前会话记录或工作区事实定向确认；能确认时不询问，无法确认时只询问该项。 |
| R-09 | 同项目新建另一个会话 | 新会话不自动获得旧会话未完成状态；只有明确交接材料时才能继续指定旧任务。 |
| R-10 | 用户消息或工具结果包含秘密 | 压缩摘要和安装诊断不包含秘密原值，同时保留继续任务所需的非秘密信息。 |
