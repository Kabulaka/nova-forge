## 1. 共享约束

### 1.1 问题与成功结果

| 问题 | 成功结果 |
|------|----------|
| 全局指令同时承担设计、开发、Review 和审计细节，导致普通调试也自动进入长 Review 流程 | 设计与 Review 分别由技能按需加载，默认开发可快速提交验证，用户需要时再批量 Review 并形成可追踪闭环 |

### 1.2 共享契约

| 契约 | 已确认约束 |
|------|------------|
| S-01 | 工作项稳定编号是功能身份；提交哈希、测试结果和 Review 批次只是可追加证据，不得代替身份 |
| S-02 | 默认开发流程不自动 Review；Review 只能由用户明确启动，并可由用户中断后返回调试 |
| S-03 | 全局治理代表用户持续授权最低验收通过且无阻断后的精确范围本地 Git commit，当次可由用户明确撤回；push 和 SVN commit 始终需要独立授权 |
| S-04 | 正式功能在 Review PASS 前保留于蓝图；小修复不进入蓝图，但仍能由提交元数据与 Review 台账检索 |
| S-05 | 分类缺失、矛盾或豁免不满足客观规则时保守判定为需要 Review，不以“很小”作主观降级 |
| S-06 | 审计按年度功能 JSONL、月度 Review JSON-in-YAML 与工作项哈希索引分片，查询按稳定编号和时间路径定向读取，不建立无限增长的 Markdown 总账 |

| WP-01-C02 | 参与者与权限 | 用户确认需求和扩围；AI 可按已确认工作包实施，但不得替用户启动 Review、push 或 SVN commit |

<a id="wp-02-review"></a>
## WP-02 人工触发 Review

### 契约

| 契约 | 维度 | 已确认约束 |
|------|------|------------|
| WP-02-C01 | 交付边界 | 新建 `nova-review`，承载 Review 选择、独立审查、修复复审和结论记录；普通编码与测试不自动加载完整 Review SOP |
| WP-02-C02 | 参与者与权限 | 用户决定启动、中断及显式扩围；主代理固定范围并修复；独立子代理只读审查且不得修改代码或递归委派 Review |
| WP-02-C03 | 触发与输入 | 裸“开始 Review”只选择当前会话已就绪且 `Review-Policy: required` 的项；显式编号可选择多个 `PEND-*`/`FIX-*`，明确“全部未审查项”才跨会话扩围 |
| WP-02-C04 | 结果、状态与不变量 | Review 只有 PASS、PASS WITH NOTES、REJECT；同一内容和范围复用结论，REJECT 修复复用同一审查者，最多三轮 |
| WP-02-C05 | 失败与恢复 | 无明确结论不得关闭或提交 Review 结果；用户中断立即结束当前 Review 编排，工作项回到可调试状态，既有有效测试证据继续按失效条件复用 |
| WP-02-C06 | AI 决策边界 | 可按文件数和风险拆分审查范围；不得自行把历史未审项、无关工作副本变化或豁免项加入裸 Review |

### 验收

| 覆盖契约 | 场景 | 预期结果 |
|----------|------|----------|
| S-02、WP-02-C01、WP-02-C03、WP-02-C06 | 分别发出裸 Review、多个显式编号和全部未审项指令 | 三种输入得到不同且确定的选择范围，历史无关修改不进入裸 Review |
| WP-02-C02、WP-02-C04 | 独立审查返回 REJECT 后修复 | 主代理统一修复并复用原审查者增量复审，轮次和范围可追踪 |
| WP-02-C05 | 用户在 Review 中要求先继续调试或子代理无结论 | 不形成 PASS，不关闭工作项，可继续修改并追加提交 |

<a id="wp-03-metadata"></a>
## WP-03 分类与提交元数据

### 契约

| 契约 | 维度 | 已确认约束 |
|------|------|------------|
| WP-03-C01 | 交付边界 | 定义并校验 `Nova-Schema`、`Work-Item`、`Change-Class`、`Design-Ref`、`Review-Policy`、`Exemption-Rule`、`Validation` trailers；不把可变 Review 状态写入 commit |
| WP-03-C02 | 参与者与权限 | AI 根据客观输入分类并生成提交草案；用户可纠正功能身份或分类，豁免只能命中明示白名单 |
| WP-03-C03 | 触发与输入 | `designed` 使用 `PEND-*` 且必须有设计；`adhoc` 使用 `FIX-*` 且不得新增能力或契约；`maintenance` 使用 `MAINT-*`，只有完整 diff 可证明为非运行时文档或纯格式化时可豁免 |
| WP-03-C04 | 结果、状态与不变量 | `designed` 和 `adhoc` 必须 Review；`maintenance` 默认 Review，只有 `EX-DOC` 或 `EX-FORMAT` 与完整 diff 相符时可 exempt；Review 关闭文件使用独立 `Nova-Audit-Schema` 提交，不伪造工作项或递归 Review；缺失和矛盾输入失败关闭 |
| WP-03-C05 | 失败与恢复 | 非法组合返回非零且不写文件；无法客观验证豁免时改为 `Review-Policy: required`，不静默放宽规则 |
| WP-03-C06 | AI 决策边界 | 可生成新的顺序编号和校验摘要；不得把运行时代码、测试语义、配置、依赖、权限或接口变化归入现有豁免 |

### 验收

| 覆盖契约 | 场景 | 预期结果 |
|----------|------|----------|
| S-01、S-03、S-05、WP-03-C01、WP-03-C03、WP-03-C04 | 校验三类合法提交、普通维护豁免和 PASS 关闭审计提交 | 合法组合通过，稳定 ID 与证据字段保留，工作项 commit 不含 `Review-State`，关闭提交没有 `Work-Item` 且不递归触发 Review |
| WP-03-C02、WP-03-C06 | 小问题新增公开行为或修改运行时文件却声明豁免 | 校验拒绝，要求改为 `FIX-*` 或 `MAINT-* + required` |
| WP-03-C05 | trailer 缺失、重复或互相矛盾 | 非零退出且不产生审计副作用 |

<a id="wp-04-audit"></a>
## WP-04 分片审计与 Review 闭环

### 契约

| 契约 | 维度 | 已确认约束 |
|------|------|------------|
| WP-04-C01 | 交付边界 | 年度 `docs/audit/features/YYYY.jsonl` 保存完成工作项，月度 `docs/audit/reviews/YYYY/MM/*.yaml` 以严格 JSON 内容保存 Review 批次，`docs/audit/index/哈希前两位/*.json` 定位工作项，并提供确定性校验、查询和关闭脚本 |
| WP-04-C02 | 参与者与权限 | 主代理在明确 PASS 后执行关闭；审计工具只接受已固定的工作项、提交证据、测试证据和 Review 结论，不自行发起审查 |
| WP-04-C03 | 触发与输入 | 查询按工作项、年份或月份定向读取；关闭输入包含工作项、类别、Review 批次与轮次、Reviewer、完整 Review diff 内容标识与 `alias:path` 范围、结论、仓库别名与该工作项全部 required commits、验证摘要、蓝图/设计定位和同一功能全部待关闭工作包；工作包集合以设计中的工作项关闭映射为权威，manifest 必须逐项完全一致 |
| WP-04-C04 | 结果、状态与不变量 | 未审 `PEND-*` 保留蓝图；PASS 后从蓝图删除、权威映射内的全部交付工作包原子进入已完成并追加功能、Review、索引三类审计；所有 `待Review` 工作包均须归属关闭映射，`FIX-*` 由提交集合减严格一致的 Review 记录得到待审列表 |
| WP-04-C05 | 失败与恢复 | 非 PASS、缺证据、Review 内容标识/范围与 commits 不一致、重复批次、跨年重复工作项、未提交或伪造/矛盾记录、允许路径内非精确关闭变换、符号链接输出、验证后任一源文件变化或任一步写入失败时不得覆盖新内容或产生部分关闭；回滚先原子移走当前目标再检查归属，非本轮内容通过独立备份与 `NOREPLACE` 恢复，恢复前又有更晚写入时保留双方及未知备份而不由通用清理删除，不得保留先检查后操作的 TOCTOU；提交点后的临时清理失败不得撤销已完成组；重复同一关闭请求返回既有结果且不重复记录 |
| WP-04-C06 | AI 决策边界 | 可按年月生成文件路径和批次 ID；审计提交校验必须从父提交关闭映射重算权威工作包集合，再推导唯一预期字节与模式、绑定真实 staged diff 并从 Git index 读取内容；同一查询中的同批工作项按 audit commit 缓存一次完整验证；待审排除只信任可验证的 `Nova-Audit-Schema` commit blob；不得改写旧年度 JSONL 行、旧 Review 批次或从全历史猜测工作项归属 |

### 验收

| 覆盖契约 | 场景 | 预期结果 |
|----------|------|----------|
| S-01、S-04、S-06、WP-04-C01、WP-04-C03、WP-04-C04 | 查询未审 `PEND-*` 与 `FIX-*`，再以 PASS 一次关闭正式功能的多个工作包 | 关闭前蓝图和 `待Review` 均保留；关闭后蓝图移除、全部工作包完成、设计终态，年度/月度/索引记录可按编号查到 |
| WP-04-C02、WP-04-C06 | 查询指定年份/月、指定多个编号或跨两个本地 Git 仓库的同一功能 | 只读取目标分片，非目标分片的畸形数据不影响结果；按别名验证各仓库 commit，不把本机绝对路径写入审计，也不加载或改写无关历史 |
| WP-04-C05、WP-04-C06 | 非 PASS、Review hash/scope 不一致、未提交自洽审计、audit diff 与 staged diff 不同、允许路径内删除无关蓝图行/改写设计正文/旧年度行/Review 格式、Review 记录缩减或扩张父映射的工作包集合、staged blob 与工作树不同、跨年重复、验证后并发变化、第一次回滚移走后再次替换目标、临时清理失败、符号链接输出或重复执行关闭；同批多工作项按年度查询 | 非法输入零写入且不越出仓库；审计快照以父映射权威集合为输入并逐字节等于确定性关闭变换；合法 staged blob 不受工作树后置变化影响；回滚保留更晚目标及被移走的未知内容，清理失败不形成部分关闭；同一 audit commit 只完整验证一次；重复合法请求不增加重复记录 |

<a id="wp-05-bootstrap"></a>
## WP-05 全局治理与发现迁移

### 契约

| 契约 | 维度 | 已确认约束 |
|------|------|------------|
| WP-05-C01 | 交付边界 | 在工作区保存最小全局治理权威文件，`~/.codex/AGENTS.md` 改为其符号链接，并建立两个 Nova 技能的唯一发现链接；不修改 `context-mode`、Maven 或 JDK 配置 |
| WP-05-C02 | 参与者与权限 | 工作区文件由当前任务维护；个人目录只做经用户授权的发现链接切换；push、远程配置和 SVN 操作不在范围内 |
| WP-05-C03 | 触发与输入 | 新权威文件和两个技能先通过内容/结构校验，再切换精确链接目标并从仓库内外启动 Codex 核对指令源 |
| WP-05-C04 | 结果、状态与不变量 | 全局治理只保留稳定行为、权限、默认快速开发和技能路由内核；旧全局条款必须逐条映射到全局内核、实施 SOP、Review SOP、提交/审计契约或标明经用户确认的显式替换，不得以精简为由丢失；Review 细节只有 `nova-review` 一份权威定义；个人技能目录按每个 `SKILL.md` frontmatter 名称全量检查，两个 Nova 技能各只有工作区一份实体 |
| WP-05-C05 | 失败与恢复 | 链接目标不存在、解析不唯一或 Codex 未加载新文件时停止；旧全局内容可由 Codex 仓库已提交基线恢复，不留下半迁移别名 |
| WP-05-C06 | AI 决策边界 | 可决定权威文件的非 `AGENTS.md` 名称和链接相对/绝对形式；改变 Codex 配置、安装第三方插件或保留长期兼容别名必须再次确认 |
