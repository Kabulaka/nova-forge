## 1. 共享约束

### 1.1 问题与成功结果

| 问题 | 成功结果 |
|------|----------|
| 新建 `PEND-*` 完成澄清、蓝图和设计后缺少确定的实施转换，导致相同任务有时编码、有时停在文档交付 | 非 Plan mode 且用户未限定仅规划时，文档校验通过即连续进入实施；只有明确暂停或实施阻断才停止 |

### 1.2 共享契约

| 契约 | 已确认约束 |
|------|------------|
| S-01 | 文档交付不是默认开发任务的终态；新建 `PEND-*` 的已确认设计和蓝图校验通过后，下一状态是实施交接 |
| S-02 | “仅规划、仅澄清、仅蓝图、仅设计、仅文档”、用户明确暂停或取消，以及 Plan mode 尚未批准，都阻止自动编码 |
| S-03 | 待确认差量、研究证据不足、文档校验失败、契约冲突或无法安全隔离既有工作副本变化属于实施阻断，必须保留可恢复状态并报告 |
| S-04 | 自动交接只覆盖编码、最低验收、证据和精确范围本地提交；Review、push、远程配置和 SVN commit 的独立授权边界不变 |

## WP-01 自动实施交接

### 契约

| 契约 | 维度 | 已确认约束 |
|------|------|------------|
| WP-01-C01 | 交付边界 | 修改 `nova-brainstorming` 的需求收敛到实施交接规则及其回归测试；不改变需求内容、Review 编排或远程提交能力 |
| WP-01-C02 | 参与者与权限 | 用户确认需求、文档写入和范围限制；AI 在非 Plan mode 的默认开发范围内连续实施，不再次询问是否编码 |
| WP-01-C03 | 触发与输入 | 本轮新建 `PEND-*`，工作包状态为已确认，蓝图引用和可执行验收完整，蓝图与设计校验通过，且用户未限定仅规划或明确暂停时触发 |
| WP-01-C04 | 结果、状态与不变量 | 状态按“已确认文档 → 文档校验通过 → 实施交接 → 编码与最低验收 → 待Review”推进；不得把文档交付回复作为中间终点 |
| WP-01-C05 | 失败与恢复 | Plan mode 未批准、用户限制或暂停、待确认差量、研究失败、校验失败、契约冲突和无法隔离历史修改时停止；条件解除后沿同一工作项继续 |
| WP-01-C06 | AI 决策边界 | 可决定实现细节和最低测试范围；不得把自动实施扩展为自动 Review、push、远程配置、SVN commit 或无关待办实施 |

### 验收

| 覆盖契约 | 场景 | 预期结果 |
|----------|------|----------|
| S-01、WP-01-C01、WP-01-C03、WP-01-C04 | 非 Plan mode 的新功能请求经澄清并确认写入，新 PEND 的蓝图与设计校验通过 | 同一执行周期立即固定实施基线并进入编码，不输出仅含文档路径的终止回复，也不再次询问是否开始编码 |
| S-02、WP-01-C02、WP-01-C05 | 用户明确“只做规划/文档”、要求暂停，或当前为尚未批准的 Plan mode | 停在文档或批准边界，不编辑实现文件 |
| S-03、WP-01-C05 | 设计仍待澄清、文档校验失败、研究证据不足、契约冲突或工作副本无法安全隔离 | 报告具体阻断并保留同一工作项，不伪造已进入实施或完成状态 |
| S-04、WP-01-C06 | 文档校验通过并自动进入实施 | 只执行当前工作项的编码、测试、证据和本地提交，不自动启动 Review，不执行远程或 SVN 操作 |
