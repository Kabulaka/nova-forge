## 1. 共享约束

### 1.1 问题与成功结果

| 问题 | 成功结果 |
|------|----------|
| 顺序数字编号依赖一个共享计数视角，多 worktree、多主机和团队并行时可能撞号或各自生成不同的“下一个编号” | 每个开发者可离线生成全局低碰撞的工作项 ID，不需要登记表、锁、计数器或主机协调 |

### 1.2 共享契约

| 契约 | 已确认约束 |
|------|------------|
| S-01 | 新工作项使用 `PEND-UUIDv7`、`FIX-UUIDv7` 或 `MAINT-UUIDv7`，UUID 采用小写规范文本，前缀由变更分类唯一决定 |
| S-02 | 既有纯数字工作项继续合法且不得迁移、改写或换号 |
| S-03 | 工作项 ID 在创建时固定；Review、修复提交和审计只消费并沿用该 ID，不创建替代 ID |
| S-04 | UUIDv7 由本机时间戳和标准库安全随机位无状态生成，不读取仓库登记文件，不依赖分支、worktree、锁、计数器、worker ID 或网络 |

## WP-01 工作项 UUIDv7 生成与兼容校验

### 契约

| 契约 | 维度 | 已确认约束 |
|------|------|------------|
| WP-01-C01 | 交付边界 | 为 Nova 工具增加 `new-id --class` 命令并接受 `designed`、`adhoc`、`maintenance`，让现有提交、选择、查询和审计路径接受 UUIDv7 工作项；不新增登记表、状态文件或工作流阶段 |
| WP-01-C02 | 参与者与权限 | 调用方先按现有契约确定变更分类，再本地生成一次 ID；Review 只能读取和沿用提交中已有 ID |
| WP-01-C03 | 触发与输入 | 新建工作项时输入三类之一；校验输入接受分类匹配的 UUIDv7 或既有纯数字 ID |
| WP-01-C04 | 结果、状态与不变量 | 新 ID 的前缀正确，UUID 为小写规范文本、版本 7、RFC 4122 variant；同一功能的全部后续提交、Review 和审计保持原 ID 不变 |
| WP-01-C05 | 失败与恢复 | 未知分类、畸形 UUID、非版本 7、非规范大小写或前缀与分类不符时返回非零且不写文件；原有数字 ID 仍可继续处理 |
| WP-01-C06 | AI 决策边界 | 可在任务创建阶段调用生成器；不得在 Review 中补造编号、替换编号，或为实现唯一性引入共享基础设施 |

### 验收

| 覆盖契约 | 场景 | 预期结果 |
|----------|------|----------|
| S-01、S-04、WP-01-C01、WP-01-C03、WP-01-C04 | 分别为三类生成 ID，并在同一进程批量生成 2000 个 | 前缀、UUID 版本和 variant 正确，批量结果无重复且不产生状态文件 |
| S-02、WP-01-C03、WP-01-C05 | 校验既有数字 ID，以及 UUIDv4、大写 UUIDv7、错误 variant、错误前缀和畸形文本 | 数字 ID 继续通过，非法新格式全部失败关闭 |
| S-03、WP-01-C02、WP-01-C04、WP-01-C06 | UUIDv7 工作项进入提交校验及后续 Review 选择、查询或关闭链路 | 全链路逐字保留原 ID，Review 不生成或替换工作项 |
