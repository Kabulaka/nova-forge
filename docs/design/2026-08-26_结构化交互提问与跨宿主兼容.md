<a id="wp-01-structured-question"></a>
## WP-01 结构化交互提问与跨宿主兼容

### 契约

| 契约 | 维度 | 已确认约束 |
|------|------|------------|
| WP-01-C01 | 交付边界 | 调整访谈问题的呈现方式并增加 Claude Code 个人发现入口；不修改 Codex/Claude Code 全局配置，不强制所有问题选项化 |
| WP-01-C02 | 参与者与权限 | 用户控制 Plan mode、功能开关和最终选择；AI 只能使用本轮实际暴露的工具，不得替用户切换模式或配置环境 |
| WP-01-C03 | 触发与输入 | 输入为阶段结论、当前唯一差量、可解释的 2–3 个互斥方案和宿主当前工具能力；开放式事实问题不要求生成选项 |
| WP-01-C04 | 结果、状态与不变量 | 普通回复先给出不要求作答的阶段总结；Codex 用可用的 `request_user_input`，Claude Code 用可用的 `AskUserQuestion`；同一问题只呈现一次 |
| WP-01-C05 | 失败与恢复 | 工具不可用、选项不诚实或问题开放时使用一个普通文本问题；工具是否已呈现无法确认时停止，不追加可能重复的问题 |
| WP-01-C06 | AI 决策边界 | 可根据已确认事实组织推荐顺序和选项说明；自行调用 `EnterPlanMode`、修改功能开关、编造选项或取消阶段总结必须再次确认 |

### 验收

| 覆盖契约 | 场景 | 预期结果 |
|----------|------|----------|
| S-01、WP-01-C02、WP-01-C03、WP-01-C04 | Codex Plan mode 或普通模式实际提供 `request_user_input` | 先显示阶段总结，再由工具显示一个问题和 2–3 个互斥选项 |
| S-01、WP-01-C02、WP-01-C03、WP-01-C04 | Claude Code 实际提供 `AskUserQuestion` | 使用同一单问题与选项约束，不要求 Codex 专属配置 |
| WP-01-C03、WP-01-C05 | 原生工具不可用或当前问题是开放式事实问题 | 只输出一个普通文本问题，不伪造选项或调用不存在的工具 |
| WP-01-C04、WP-01-C05 | 已输出阶段总结并准备调用原生工具 | 普通回复不重复问题；工具呈现状态不确定时不二次发问 |
| WP-01-C01、WP-01-C02、WP-01-C06 | 在 Codex 普通模式或 Claude Code 中希望获得可点击选项 | 技能不修改全局配置、不自动切换 Plan mode，环境能力由用户决定 |
