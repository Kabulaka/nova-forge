# Nova Forge v0.8.0

2026-09-20

## Overview

Nova Forge v0.8.0 扩展共享澄清交互：当问题存在 2–3 个真实互斥选项且当前通道支持时，阻塞选择和非阻塞可选偏好都可以使用宿主的原生结构化提问。问题是否阻塞只决定没有有效答案时如何推进，不再决定是否允许显示原生选择框。

## Highlights

### 统一选择式澄清

- Codex 使用可用的 `request_user_input`，Claude Code 使用可用的 `AskUserQuestion`，推荐项保持第一位。
- 原生选择只承载业务范围、行为、契约、设计或偏好选项，不承担权限审批、提权或破坏性操作授权。
- 开放式事实问题和无法形成诚实互斥选项的问题继续使用普通文本。

### 通道能力与恢复边界

- 明确区分“工具出现在列表中”和“当前交互通道实际可用”；`codex exec`、批处理等非交互通道必须使用普通文本。
- 能力错误或无法确认问题已成功呈现时，立即以普通文本完整降级；已确认呈现但未回答的阻塞选择保持待确认。
- 非阻塞选择只有在提问前已披露默认处理时，才能在确认呈现但未回答后按默认继续。

### 验证覆盖

- 插件结构测试固定阻塞与非阻塞选择、权限审批边界、非交互降级和空答案恢复规则。
- Codex 0.155.0 隔离验收确认：开启 Default mode 结构化提问 feature 后，阻塞和非阻塞选择均产生原生选择事件，真实 TUI 可以显示并提交答案。

## Installation

### Codex CLI

```bash
codex plugin marketplace add Kabulaka/nova-forge --ref v0.8.0
codex plugin add nova-forge@nova-forge
```

### Claude Code

```text
/plugin marketplace add Kabulaka/nova-forge
/plugin install nova-forge@nova-forge
```

## Requirements

- Node.js 22.5 或更高版本；插件不会自动安装 Node.js 或 Bun。
- 支持插件 marketplace 的 Codex CLI，或 Claude Code 2.1.233 及兼容版本。
- Codex 0.155.0 在 Default mode 使用原生选择框时，需要宿主启用 `[features].default_mode_request_user_input = true`；未启用或通道不支持时使用普通文本降级。
- 安装后审阅并信任插件 Hook，并在升级后新开宿主会话。

## Upgrade Notes

- Codex 用户把 marketplace 固定引用更新为 `v0.8.0`，重新安装或刷新插件后新开会话。
- Claude Code 用户先更新 `nova-forge` marketplace，再更新或重新安装 `nova-forge@nova-forge`，随后新开会话。
- 原生结构化提问是否可用仍由宿主版本、feature 和交互通道决定；Nova Forge 不会自行切换 Plan mode 或修改宿主配置。
- 本版本不迁移现有蓝图、设计、业务代码或需求文档，也不增加状态机、台账或持久缓存。
