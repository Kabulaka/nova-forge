# Nova Forge v0.6.1

> 收紧架构事实边界，让功能设计回归 Development

## Overview

Nova Forge v0.6.1 修复 `nova-architecture` 会把具体功能流程、算法、恢复步骤和未来测试清单泛化为架构的问题。Architecture 现在只维护约束项目整体或多个独立参与方长期兼容的共享边界；单模块功能与实现方案继续由 Development 负责。

## Highlights

### 明确的架构事实准入

只有项目级技术栈、运行实体、模块职责与依赖方向，或者多个能够独立变化的参与方直接消费的公共 API、数据、事件和基础设施边界，才能进入架构。功能碰巧调用多个模块不再自动升级为架构，单模块通过私有适配器访问的供应商也不构成新的架构参与方。

### 混合请求保持完整闭环

用户在架构讨论中提出具体功能时，Architecture 会先完成其中真正的共享边界，再限域交给 Development 进行功能澄清、设计和待开发登记，不编写实现。Development 返回后由 Architecture 继续原架构生命周期；Development 提出的疑似架构冲突仍须重新通过 Architecture 准入，不能反向决定架构。

### 更轻量的蓝图初始化

空白项目默认只创建 `.nova/PROJECT_BLUEPRINT.md`。跨模块调用流程、编排、恢复矩阵、供应商匹配或回退策略以及未来测试清单不会为了填充开发导航而生成详细架构文档。只有多个独立参与方直接消费的精确版本化契约，才使用 `.nova/architecture/<topic>.md`。

## Fixes

- Gateway 与 Control 等运行实体可以保留在蓝图中，同时把生命周期、Redis 算法、事务、重试和恢复步骤留给 Development。
- 价格来源、匹配、优先级、回退、预览确认和发布流程被明确归为 Pricing 功能开发内容。
- 蓝图模板明确禁止把某个功能的实现说明、恢复矩阵或未来测试清单登记为共享架构。
- 增加结构契约回归测试，覆盖架构准入、Development 限域交接及返回后的重新判定。

## Installation

### Codex CLI

```bash
codex plugin marketplace add Kabulaka/nova-forge --ref v0.6.1
codex plugin add nova-forge@nova-forge
```

### Claude Code

```text
/plugin marketplace add Kabulaka/nova-forge
/plugin install nova-forge@nova-forge
```

## Requirements

- Node.js 22.5 或更高版本；插件不会自动安装 Node.js 或 Bun。
- 支持插件 marketplace 的 Codex CLI，或 Claude Code 2.1.233 及兼容版本。
- 安装后审阅并信任插件 Hook，并在升级后新开宿主会话。

## Upgrade Notes

- Codex 用户把 marketplace 固定引用更新为 `v0.6.1`，重新安装或刷新插件后新开会话。
- Claude Code 用户先更新 `nova-forge` marketplace，再更新或重新安装 `nova-forge@nova-forge`，随后新开会话。
- 本次升级不迁移或自动删除既有 `.nova/architecture/` 文档；需要调整旧蓝图时仍由用户明确调用 Architecture。
- Development 技能及其普通实现流程没有变化。
