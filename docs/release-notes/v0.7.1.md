# Nova Forge v0.7.1

2026-09-18

## Overview

Nova Forge v0.7.1 修复 `nova-development` 在外部参考研究、架构判断、设计澄清和同任务续改中的三个执行缺口。Development 现在对缺失研究证据保持失败封闭，使用单一系统骨架封闭集判断架构冲突，并复用未变化的技能、蓝图、基线和验证事实，避免把目标性描述或重复读取当作有效进展。

## Highlights

### 外部参考研究失败封闭

- 只有传输成功、正文非空且来源可定位的结果才构成外部研究证据。
- 空代理列表、单独等待、超时、空结果或末端管道命令成功都不会再被表述为独立研究或交叉核对完成。
- 外部命令要求使用 `pipefail` 或等价上游失败校验；证据不足时明确标注未验证，不声称标准兼容。

### 架构与设计边界保持一致

- Development 的轻量架构闸门使用一处权威封闭集合，其他流程引用该集合，避免多份同义规则漂移。
- 业务 API、schema、DTO、数据库表、业务事件和端到端流程继续由 Development 在既有系统骨架内处理。
- 只有目标性描述且关键契约仍有多种合理语义时先逐项澄清，不再由 AI 自选默认值补齐设计，也不会提前读取设计规范和模板。

### 减少重复准备与验证

- 准备和验证批次明确为模型工具回合，不要求把所有检查拼进一个 shell 命令。
- 事实未变化时不重读技能、蓝图、基线或任务事实；同任务续改只更新本轮差量。
- 结构契约测试覆盖外部研究证据闸门、设计延迟加载和权威架构集合。

## Installation

### Codex CLI

```bash
codex plugin marketplace add Kabulaka/nova-forge --ref v0.7.1
codex plugin add nova-forge@nova-forge
```

### Claude Code

```text
/plugin marketplace add Kabulaka/nova-forge
/plugin install nova-forge@nova-forge
```

## Requirements

- Node.js 22.5 或更高版本；插件不会自动安装 Node.js 或 Bun。
- 支持插件 marketplace 的 Codex CLI，或 Claude Code 2.1.233 及兼容版本。
- 安装后审阅并信任插件 Hook，并在升级后新开宿主会话。

## Upgrade Notes

- Codex 用户把 marketplace 固定引用更新为 `v0.7.1`，重新安装或刷新插件后新开会话。
- Claude Code 用户先更新 `nova-forge` marketplace，再更新或重新安装 `nova-forge@nova-forge`，随后新开会话。
- 本版本不迁移现有蓝图、设计、业务代码或需求文档，也不增加状态机、台账或持久缓存。
- Development 的架构边界保持兼容；业务契约不会因为跨模块、共享或版本化而自动转入 Architecture。
