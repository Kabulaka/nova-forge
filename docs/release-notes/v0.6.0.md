# Nova Forge v0.6.0

> 按需澄清整体业务需求，同时保持日常开发流程轻量解耦

## Overview

Nova Forge v0.6.0 新增人工触发的 `nova-requirements` 技能，用于在绿地系统或总体业务范围尚未明确时澄清“业务如何运转”，并按需生成轻量需求文档。需求只保留业务目标、参与者责任、端到端流程、关键行为规则与范围边界，不维护实现状态，也不会被 Architecture、Development、Review 或 Commit 自动发现和加载。

## Highlights

### 独立的轻量需求技能

`nova-requirements` 只在用户明确要求澄清、新增、查看、修改或删除业务需求时执行。它不创建需求编号、版本、状态、实现依据或交付台账，也不自动转入架构、开发、Review 或提交。

### 面向业务运转的需求文档

新的业务需求模板以目标与边界、参与者、业务流程、关键行为规则和范围边界为主体。复杂系统可增加“业务能力与边界”总览；单一业务主线会省略该章节并连续调整编号。随包提供 AI 模型网关完整示例，区分套餐额度等业务承诺与流控算法、存储、接口路径等实现选择。

### 更可靠的澄清交互

Requirements、Architecture 与 Development 共用同一套澄清 SOP。只有系统名称或抽象目标时，需求首问会先询问现实问题和期望结果，不预设产品模式；结构化提问无法确认成功呈现时，会在同一轮完整降级为普通文本问题。

### 明确的架构与开发边界

新增或删除项目级模块、技能，或者改变共享职责与公共边界时，先由 Architecture 完成架构决定，再由 Development 实现。单一模块内、不改变共享边界的普通能力仍由 Development 直接完成。

## Features

- Codex 与 Claude Code 插件均暴露 requirements、architecture、development、review、commit 五个技能。
- 发布包与开发快照包含需求技能、业务需求模板和 AI 网关示例。
- 需求澄清沿业务责任链推进，不按角色、状态、权限或验收栏目逐项审问。
- 完整业务大纲形成后立即停止提问；实现参数与低风险细节留给后续开发。
- 需求文档完全由人工增删改查，其他技能不会为普通开发主动读取或同步需求。

## Installation

### Codex CLI

```bash
codex plugin marketplace add Kabulaka/nova-forge --ref v0.6.0
codex plugin add nova-forge@nova-forge
```

### Claude Code

```text
/plugin marketplace add Kabulaka/nova-forge
/plugin install nova-forge@nova-forge
```

## Requirements

- Node.js 22.5 或更高版本；插件不会自动安装 Node.js 或 Bun。
- 支持插件 marketplace 的 Codex CLI，或 Claude Code 2.1.233 及兼容版本。
- 安装后审阅并信任插件 Hook，并在升级后新开宿主会话。

## Upgrade Notes

- Codex 用户把 marketplace 固定引用更新为 `v0.6.0`，重新安装或刷新插件后新开会话。
- Claude Code 用户先更新 `nova-forge` marketplace，再更新或重新安装 `nova-forge@nova-forge`，随后新开会话。
- 本次升级不要求迁移既有需求文档；`nova-requirements` 只处理用户本次明确指定的内容和文件。
- 日常 Development 不会自动读取需求文档。需要让实现遵循某份需求时，请在开发请求中明确提供内容或精确路径。
- `nova-requirements` 不恢复旧版 REQ 需求块、状态、检查点或需求到实现的结构化追踪。
