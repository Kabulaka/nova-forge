# Nova Forge v0.4.0

> 将 Nova Forge 重构为低开销、人工主导的开发 SOP

## Overview

Nova Forge v0.4.0 将产品目标从自动化交付治理框架调整为辅助 Codex 与 Claude Code 高效开发的轻量 SOP。普通开发现在直接进入范围确认、实现和测试；只有真实歧义才澄清，架构修改、Review 与本地提交都由用户明确发起。

这是一个不兼容版本：需求治理、Doctor、MCP 检查点、审计、状态机和交付台账不再属于插件能力。升级前依赖这些机制的项目应先评估替代方案。

## Highlights

### Four Focused Skills

插件聚焦 `nova-architecture`、`nova-development`、`nova-review` 和新增的 `nova-commit`。架构技能在蓝图缺失时初始化蓝图；蓝图存在后，普通开发只读取并遵循现有架构，只有用户主动调用时才修改共享架构。Review 和提交均与开发解耦，避免一次实现尚未稳定时过早审查或提交。

### Lower-Overhead Development

明确的开发请求不再经过需求块、工作项编号、交付台账、审计和检查点状态流转。Architecture 与 Development 共用单问题澄清协议，只在会改变实现或路由的真实歧义上提问；完成报告改为提示词约束，不再创建临时报告或运行格式校验。

### Explicit Human Control

普通开发不会自动修改架构、扫描设计目录、启动 Review 或创建提交。设计文件仍可保留为历史资料，但只有蓝图为当前目标提供精确链接时才读取。Review 保留独立 Reviewer、显式思考度、问题分级、最多三轮修复复审等核心约束，并仅在用户明确要求时运行。

### Simplified Host Integration

Codex 与 Claude Code 只保留 `SessionStart` Hook，用于注入稳定的 Nova 路由和工作约定。插件不再启动 MCP server，也不再维护 Nova 自有的检查点、压缩续接、状态根、迁移或审计数据；会话连续性回归宿主原生能力。

## Features

- 新增专用 `nova-commit`，只负责检查当前任务差异、执行最低必要验证并创建一个 Conventional Commit。
- 普通功能、局部调整、缺陷恢复和维护统一由 `nova-development` 直接处理，明确请求可减少不必要的模型往返。
- 蓝图承担共享架构导航；详细架构文档仅在需要时由蓝图精确链接。
- Codex 和 Claude Code 使用同一组四项技能及一致的人工触发边界。

## Installation

### Codex CLI

```bash
codex plugin marketplace add Kabulaka/nova-forge --ref v0.4.0
codex plugin add nova-forge@nova-forge
```

### Claude Code

```text
/plugin marketplace add Kabulaka/nova-forge
/plugin install nova-forge@nova-forge
```

## Requirements

- Node.js 22.5 或更高版本；插件不会自动安装 Node.js 或 Bun。
- 支持插件 marketplace 的 Codex CLI，或 Claude Code 2.1.233 及兼容版本。
- 安装后审阅并信任插件 Hook，并在升级后新开宿主会话。

## Upgrade Notes

- Codex 用户把 marketplace 固定引用更新为 `v0.4.0`，重新安装或刷新插件后新开会话。
- Claude Code 用户先更新 `nova-forge` marketplace，再更新或重新安装 `nova-forge@nova-forge`，随后新开会话。
- 本版本不再提供 `nova-requirements`、`nova-doctor`、Nova MCP 检查点、审计、状态机、迁移校验、工作项编号或 Review 状态管理。依赖这些能力的自动化流程必须在升级前移除或替换。
- 插件不会主动扫描 `.nova/design/`；只有蓝图给出与当前目标相关的精确链接时才读取对应设计。历史设计可以继续保留。
- 旧项目中的需求、审计、交付和检查点文件不会由本版本继续维护，也不会被自动迁移或删除；如仍有保留需求，应在升级前自行归档。
- Review 和 commit 不再随开发自动运行。完成实现后，分别显式调用 `nova-review` 和 `nova-commit`。
- 移除 Nova 自有检查点后，长会话和压缩续接依赖 Codex 或 Claude Code 的原生能力。
