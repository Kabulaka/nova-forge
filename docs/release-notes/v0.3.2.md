# Nova Forge v0.3.2

> 修复 Codex 与 Claude Code 的回合检查点及压缩续接连续性

## Overview

Nova Forge v0.3.2 修复双宿主在真实生命周期事件顺序下可能丢失检查点连续性的问题。Codex 与 Claude Code 现在分别按宿主实际的压缩完成顺序恢复同一代权威检查点；检查点未覆盖当前事件水位、压缩握手不完整或恢复胶囊超限时，Nova 会保持可见降级并放行宿主会话，不再把未完成注入记录为成功。

## Highlights

### Host-Ordered Compaction Continuity

Codex 在 `PostCompact` 完成后由 `SessionStart(compact)` 注入恢复胶囊。Claude Code 允许 `SessionStart(compact)` 先于 `PostCompact` 到达，并在压缩完成后的下一次可信 `UserPromptSubmit` 前注入同一代胶囊。合法的 Claude Code 待完成顺序不再被误报为连续性失败。

### Checkpoint Safety and Diagnostics

回合规则现在明确要求在结束前保存覆盖当前 `eventWatermark` 的结构化检查点，并为两个宿主使用各自完整的 MCP 工具名。只有恢复上下文完整构建成功后才记录 `injectedGeneration`；胶囊构建、追加或恢复超限时记录 `COMPACTION_INJECTION_FAILED`，保留 dirty 状态并拒绝提升无效 authority。

### Dual-Host Configuration Consistency

Codex 与 Claude Code 的开发安装和 MCP 配置会一致传递显式 `NOVA_HOME`。检查点 schema 对 `stageProjection.resolutionBasis` 的输入边界同步收紧，只接受 `user-confirmed`、`verified-evidence`、`delegated-ai-candidate` 或 `explicitly-excluded`，不再接受 `pending` 作为已解决依据。

## Fixes

- 修复 Claude Code 的 `SessionStart(compact)` 早于 `PostCompact` 时错误降级且无法在下一提示前恢复的问题。
- 修复恢复胶囊构建失败后仍可能写入 `injectedGeneration`、造成虚假成功状态的问题。
- 修复恢复内容达到总大小、追加 turn context 或恢复字段边界时缺少确定性失败状态的问题。
- 补齐 Codex 与 Claude Code 每回合检查点工具名、保存水位和 authority 字段约束，避免未覆盖水位被误作可恢复状态。
- 补齐 `NOVA_HOME` 在 Codex MCP 与开发插件安装快照中的传递和结构校验。

## Installation

### Codex CLI

```bash
codex plugin marketplace add Kabulaka/nova-forge --ref v0.3.2
codex plugin add nova-forge@nova-forge
```

### Claude Code

```text
/plugin marketplace add Kabulaka/nova-forge
/plugin install nova-forge@nova-forge
```

## Requirements

- Node.js 22.5 或更高版本；插件不会自动安装 Node.js 或 Bun。
- 支持插件 marketplace 的 Codex CLI，或 Claude Code 2.1.233 及兼容版本。
- 安装后审阅并信任插件 Hook，并在升级后新开宿主会话。

## Upgrade Notes

- Codex 用户把 marketplace 固定引用更新为 `v0.3.2`，重新安装或刷新插件后新开会话。
- Claude Code 用户先更新 `nova-forge` marketplace，再更新或重新安装 `nova-forge@nova-forge`，随后新开会话。
- 本版本不改变检查点 schema 版本或默认 `~/.nova`/绝对 `NOVA_HOME` 状态根，满足现行结构约束的检查点无需格式迁移；旧状态若把 `pending` 写入 `resolutionBasis`，将失败封闭且不会成为恢复 authority，需要在新会话保存符合约束的完整检查点。
- `CHECKPOINT_NOT_COVERED` 仍表示当前事件水位尚未被最新检查点覆盖；该保护不会阻断普通回答或宿主原生压缩，也不应被当作跨会话绑定错误。
- 同一 PID、同一目录或单个 MCP runtime 中的多个会话继续由每次工具调用的一次性 `scopeProof` 路由，不依赖进程或 MCP instance 数量；证明缺失、错配、伪造、过期或重放时，MCP 会在访问检查点前失败封闭。
- 双宿主原生端到端验收已在 Linux 完成；Windows 与 macOS 本轮覆盖确定性契约测试，尚未执行原生双宿主端到端验收。
- 已发布的 `v0.3.1` 标签和资产保持不可变。
