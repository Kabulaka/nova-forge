# Nova Forge v0.5.0

> 让蓝图成为唯一的按需开发导航，并在编码前识别架构变动

## Overview

Nova Forge v0.5.0 重新明确 Architecture、Development 与项目蓝图的关系：蓝图维护多人长期开发共同遵守的主体架构，并用一张按触发条件组织的开发导航指向相关契约、代码和测试。普通开发只读取当前任务命中的入口，同时在首次编辑前完成轻量架构判断，避免先实现再因共享边界变化返工。

## Highlights

### 唯一开发导航

已实现共享能力与详细共享契约统一登记在蓝图第六章“开发导航”。导航提供开发触发条件、精确入口、复用或遵循边界和验证入口，不复制代码实现，也不要求扫描整个架构或设计目录。独立的 `SHARED_CAPABILITIES.template.md` 已移除。

### 长期架构闭包

`nova-architecture` 以维护多人兼容实现为核心，明确技术栈、代码结构、模块职责、公共约束、开发导航和待开发工作的权威章节及联动关系。旧蓝图迁移采用失败即停的完整映射，验证成功前保留原蓝图和旧共享能力目录。

### 编码前架构闸门

`nova-development` 使用既有蓝图和定向研究结果完成“命中 / 不命中 / 未知”三态判断，不额外扫描目录或调用外部研究。没有现有架构合规实现的硬冲突必须先调整架构或需求；存在明确合规实现的架构收益和未知风险则交由用户决定是否调用 Architecture。

## Features

- 蓝图固定为“项目定位、技术栈、代码结构、模块职责、公共约束、开发导航、待开发工作”七章顺序。
- 待开发工作移至第七章，并提供 `开发触发条件 | 待开发内容 | 交付结果 | 设计入口` 示例表。
- Development 发现旧蓝图缺少开发导航或仍存在 `.nova/SHARED_CAPABILITIES.md` 时停止普通开发并提示显式迁移，不把未命中解释为能力不存在。
- 当前项目的插件结构、SessionStart 和安装打包入口拆为三条导航，只加载各自相关的源码与验证入口。
- 开发快照和发布包强制包含唯一蓝图模板，并拒绝已移除的共享能力模板。
- 移除 Development 内重复的 Plan mode 章节；宿主和全局 Plan mode 审批边界保持不变。

## Installation

### Codex CLI

```bash
codex plugin marketplace add Kabulaka/nova-forge --ref v0.5.0
codex plugin add nova-forge@nova-forge
```

### Claude Code

```text
/plugin marketplace add Kabulaka/nova-forge
/plugin install nova-forge@nova-forge
```

## Requirements

- Node.js 22.5 或更高版本；插件不会自动安装 Node.js 或 Bun。
- 支持插件 marketplace 的 Codex CLI，或 Claude Code 2.1.233 及兼容版本。
- 安装后审阅并信任插件 Hook，并在升级后新开宿主会话。

## Upgrade Notes

- Codex 用户把 marketplace 固定引用更新为 `v0.5.0`，重新安装或刷新插件后新开会话。
- Claude Code 用户先更新 `nova-forge` marketplace，再更新或重新安装 `nova-forge@nova-forge`，随后新开会话。
- 旧蓝图第六章“待开发工作”迁至新第七章；旧第七章架构链接和经代码、测试确认的共享能力合并到新第六章“开发导航”。
- 若项目蓝图缺少“开发导航”或仍存在 `.nova/SHARED_CAPABILITIES.md`，普通 Development 会停止并提示用户显式调用 Architecture。只有新七章、待办、链接和导航全部验证通过后才移除旧目录。
- 架构硬冲突不再提供“保持现有架构开发”选项；冲突解除前必须调整架构，或修改、放弃冲突需求。
- 蓝图导航只用于发现相关入口；当前实现事实仍以代码、测试、迁移和配置为准。
