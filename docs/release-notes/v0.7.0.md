# Nova Forge v0.7.0

2026-09-17

## Overview

Nova Forge v0.7.0 重新划清项目蓝图三类内容的职责：Architecture 只维护系统骨架，Development 维护已经交付并验证的可复用能力，待开发工作继续承载大块开发需求和合格技术债务。业务 schema、业务接口和端到端功能流程不再因为跨模块、共享或版本化而被泛化为架构。

## Highlights

### 架构回归轻量系统骨架

- `nova-architecture` 只维护技术栈、运行与部署形态、基础设施职责、系统分层、稳定目录、项目级服务或模块职责以及依赖方向。
- 数据库、缓存、文件和日志的边界按长期介质职责表达，不把具体业务对象写成存储流水账。
- 业务 API、schema、DTO、数据库表、业务事件和端到端工作流留在 Development，不再创建新的详细架构文档。

### 已实现可复用能力由 Development 维护

- 蓝图第六章更名为“已实现可复用能力”，读取时继续兼容旧标题“开发导航”，不会强制迁移既有蓝图。
- 只有已经交付、具有独立验证入口、能够离开单一业务工作流复用的项目级能力才会登记。
- 单功能工作流、内部辅助代码、业务契约和潜在复用候选不会进入该章节，也不会触发 Architecture。

### 待开发工作与 Review 技术债务保持轻量

- 待开发工作允许设计入口为“无”；精确设计链接仅表示该工作已经完成设计澄清，没有链接不会阻塞用户直接发起 Development。
- `nova-review` 只在最终 PASS 或 PASS WITH NOTES 后登记证据充分、非阻塞且需要独立交付的技术债务。
- 蓝图不会增加状态、来源、负责人、优先级、进度、Review 或审计字段。

## Installation

### Codex CLI

```bash
codex plugin marketplace add Kabulaka/nova-forge --ref v0.7.0
codex plugin add nova-forge@nova-forge
```

### Claude Code

```text
/plugin marketplace add Kabulaka/nova-forge
/plugin install nova-forge@nova-forge
```

## Requirements

- Node.js 22.5 或更高版本；插件不会自动安装 Node.js 或 Bun。
- 支持插件 marketplace 的 Codex CLI，或 Claude Code 2.1.233 及兼容版本。
- 安装后审阅并信任插件 Hook，并在升级后新开宿主会话。

## Upgrade Notes

- Codex 用户把 marketplace 固定引用更新为 `v0.7.0`，重新安装或刷新插件后新开会话。
- Claude Code 用户先更新 `nova-forge` marketplace，再更新或重新安装 `nova-forge@nova-forge`，随后新开会话。
- 现有蓝图不会被自动改写；旧标题“开发导航”仍可读取，需要整体精简或迁移时显式调用 `nova-architecture`。
- 现有设计、业务代码和需求文档不会被自动迁移、删除或同步。
