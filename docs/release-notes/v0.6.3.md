# Nova Forge v0.6.3

> 收紧蓝图精简边界并减少开发路由的无效上下文

## Overview

Nova Forge v0.6.3 修复旧蓝图升级时容易把全量语义审计扩张为全仓库审计、把局部恢复细节和核验证据重新写入蓝图的问题，同时减少 `nova-development` 在局部续改与明确架构冲突场景中的重复加载。

## Highlights

### 更轻量的蓝图升级

`nova-architecture` 现在把完整审计限定为整份蓝图，只对权限、共享数据所有权、已登记公共契约和当前基础设施做有界核验。功能流程、事务重试、迟到结果、资源清理、通用治理规则和框架生成的描述版本不会换章节继续保留。

开发导航只迁移旧蓝图或固定旧入口已经登记且具备独立验证入口的能力；核验时发现的代码、配置和测试不会自动成为新导航。模块职责必须映射到精确目录或运行体，不能使用“相关模块”等模糊占位。

### 更准确的 Development 路由

`nova-development` 不再在普通开发中探测旧 `SHARED_CAPABILITIES.md`。局部、可替换且不改变共享边界的实现直接开发；用户请求与蓝图已经足以证明模块职责、依赖方向、数据所有权或公共契约冲突时立即停止，不再读取设计和代码堆叠同一结论的证据。

### 更快的同任务续改

同一内聚任务的后续收紧、验证和配置调整可以复用未失效的技能、蓝图命中结果、任务基线和测试证据，只从最早失效环节恢复，不机械重跑完整准备流程。

## Installation

### Codex CLI

```bash
codex plugin marketplace add Kabulaka/nova-forge --ref v0.6.3
codex plugin add nova-forge@nova-forge
```

### Claude Code

```text
/plugin marketplace add Kabulaka/nova-forge
/plugin install nova-forge@nova-forge
```

## Requirements

- Node.js 22.5 或更高版本；插件不会自动安装 Node.js 或 Bun。
- 支持插件 marketplace 的 Codex CLI，或 Claude Code 2.1.233 及兼容版本。
- 安装后审阅并信任插件 Hook，并在升级后新开宿主会话。

## Upgrade Notes

- Codex 用户把 marketplace 固定引用更新为 `v0.6.3`，重新安装或刷新插件后新开会话。
- Claude Code 用户先更新 `nova-forge` marketplace，再更新或重新安装 `nova-forge@nova-forge`，随后新开会话。
- 本次升级不会自动重写现有蓝图；需要升级、迁移或整体精简时仍须显式调用 `nova-architecture` 并确认写入摘要。
- 既有设计、业务代码和需求文档不会被自动迁移、删除或同步。
