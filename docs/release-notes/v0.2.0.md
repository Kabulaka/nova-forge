# Nova Forge v0.2.0

> Windows 原生审计关闭与架构继承门禁

## Overview

Nova Forge v0.2.0 让 Nova 的规划、校验、查询和 Review 关闭流程在 Ubuntu、macOS 与原生 Windows 上使用同一套失败封闭语义，并强化开发阶段对已确认架构契约的继承与验证。

## Highlights

### Windows Native Governance

- `check-manifest`、`record-pass`、`query`、Doctor 关联检查和 Review 关闭流程现在支持原生 Windows，不要求 WSL。
- `record-pass` 使用仓库级排他锁、同卷发布、持久事务日志、逻辑提交标记和幂等恢复，避免 Nova 读取方接受部分关闭结果。
- GitHub Actions 在 Ubuntu、macOS 和 Windows 上运行治理测试，并校验工作流不能静默排除 Windows。

### Architecture-Aware Development

- 开发规划和实施会先读取架构契约索引，定向加载当前工作项相关契约，并通过架构就绪校验后继续。
- 架构索引缺失、内容漂移或依据不可信时失败封闭，避免只依据蓝图摘要推断详细契约。

### Review Governance

- `current` 和 `all` 继续只发现需要 Review 的工作项；维护者可以按稳定编号显式补审尚未归档的 `EX-FIX`。
- Windows 与 POSIX 平台共享相同 manifest、审计记录、历史 Git 快照验证和确定性关闭结果。

## Features

- 新增 Windows 原生 Nova 审计关闭能力，覆盖锁竞争、故障恢复、历史兼容、CRLF 文件和路径安全检查。
- 新增开发阶段架构读取门禁，确保规划和实施继承当前已确认的共享契约。

## Fixes

- 修复开发阶段可能绕过架构索引、仅从蓝图摘要推断实现约束的问题。
- 修复 Review 事务中部分文件先行可见、清理失败误报成功、历史校验受当前符号链接状态影响等关闭边界。
- 修复 Doctor 在审计目录尚未创建时可能跳过未完成事务检查的问题。

## Installation

运行时要求 Node.js 22.5 或更高版本。私有仓库安装需要当前用户已经具备 GitHub 仓库读取权限。

### Codex CLI

```bash
codex plugin marketplace add Kabulaka/nova-forge --ref v0.2.0
codex plugin add nova-forge@nova-forge
```

### Claude Code

```text
/plugin marketplace add Kabulaka/nova-forge
/plugin install nova-forge@nova-forge
```

安装或升级后请重新审阅并信任插件 Hook，然后新开会话使技能、Hook 与 MCP 生效。

## Requirements

- Node.js 22.5 或更高版本。
- 支持插件的 Codex CLI 或 Claude Code；Codex IDE 当前使用兼容发现链接。
- 运行 Nova 治理命令需要 Python 3 标准库环境；Windows 可使用 `py -3`，不要求 WSL。
- Windows 原生关闭支持基线为本机 NTFS。

## Upgrade Notes

- 从 v0.1.0 升级时，将 Codex Git marketplace 的固定引用更新为 `v0.2.0`，刷新或重新安装插件，并新开会话。
- 本版本不需要迁移既有 Nova 审计数据；schema 1 历史记录继续只读兼容。
- 校验器现在会拒绝 mixed EOL、bare CR、不可信 clean-filter 投影、reparse point 和未完成 Review 事务。修复输入或使用同一 manifest 恢复事务后再重试，不要绕过失败封闭门禁。
- Windows 上的 SMB 网络共享、ReFS、同步盘，以及突然断电后的多文件物理同时落盘不在当前承诺范围内。
- 已使用兼容软链接的宿主仍须避免与版本化插件同时启用；切换入口后应运行 discovery 校验并新开会话。
