# Nova Forge v0.3.0

> 双宿主状态自初始化、恢复降级与检查点作用域加固

## Overview

Nova Forge v0.3.0 为 Codex 与 Claude Code 插件增加稳定用户私有状态根的自动初始化和旧状态非破坏性迁移，并让检查点异常降级为可见但不阻断宿主对话与原生压缩的状态。本版本同时用宿主签发的一次性作用域证明绑定每次检查点调用，避免模型参数选择或跨会话复用状态。

## Highlights

### Stable State Bootstrap

- 插件默认在 `~/.nova` 保存检查点，也支持在宿主启动前通过绝对路径 `NOVA_HOME` 改用其他磁盘。
- 安装器、首次 Hook 和 MCP 初始化会幂等创建状态根，并通过真实写入、同步、原子替换和删除探针确认目录可用。
- 旧版 Codex 与 Claude Code 插件数据按宿主分别验证后非破坏性迁移；旧根不会被删除，迁移中断可以安全重试。

### Authority-Safe Checkpoints

- 每次检查点查询或保存前，宿主 `PreToolUse` 都会为当前会话和工具调用签发一次性不透明作用域证明。
- MCP 原子消费并校验证明后才访问状态；缺失、伪造、过期、错配或重放的证明会在零状态访问下被拒绝。
- 检查点工具不再接受模型选择的 host 或 session ID，Codex 与 Claude Code 状态继续按宿主和会话物理隔离。

### Host Availability and Development Install

- 检查点缺失、状态根不可写、MCP 不可用或压缩握手不完整时，Nova 会明确报告无权威降级，但继续放行普通对话和宿主原生压缩。
- 双宿主开发安装支持从本地打包快照离线登记，并明确隔离 `CODEX_HOME`、`CLAUDE_CONFIG_DIR` 与 `NOVA_HOME`。
- 正在运行的旧会话可继续使用其启动时加载的插件缓存；新会话使用新安装快照。

## Features

- 新增插件状态根自动初始化、真实可写性探测、按宿主旧状态迁移和卸载后状态保留。

## Fixes

- 修复 Codex 插件 MCP 启动路径和会话绑定，使双宿主检查点查询、保存与恢复使用正确的插件根和可信会话作用域。
- 修复存活 MCP 绑定被超时清理，以及同一宿主进程内多会话或多 MCP instance 可能错误配对的问题。
- 修复检查点、状态根或压缩握手异常会阻断宿主回答和原生压缩的问题；无有效权威状态时现在显式降级。
- 修复未覆盖检查点告警重复打印、开发快照夹带 Python 字节码，以及 Doctor 技能套件测试根路径错误。
- 增加一次性作用域证明，拒绝跨会话、跨宿主、错工具调用或重放的检查点访问。

## Installation

运行时要求 Node.js 22.5 或更高版本。私有仓库安装需要当前用户已经具备 GitHub 仓库读取权限。

### Codex CLI

```bash
codex plugin marketplace add Kabulaka/nova-forge --ref v0.3.0
codex plugin add nova-forge@nova-forge
```

### Claude Code

```text
/plugin marketplace add Kabulaka/nova-forge
/plugin install nova-forge@nova-forge
```

安装或升级后请重新审阅并信任插件 Hook，然后新开会话使技能、Hook、MCP 和一次性作用域证明共同生效。

## Requirements

- Node.js 22.5 或更高版本。
- 支持插件的 Codex CLI 或 Claude Code；Codex IDE 当前使用兼容发现链接。
- 运行 Nova 治理命令需要 Python 3 标准库环境；Windows 可使用 `py -3`，不要求 WSL。
- 默认状态根为当前用户主目录下的 `~/.nova`；自定义 `NOVA_HOME` 必须是宿主启动前设置的绝对路径。

## Upgrade Notes

- 从 v0.2.0 升级时，将 Codex Git marketplace 的固定引用更新为 `v0.3.0`，刷新或重新安装插件，并新开会话。
- 旧插件数据只作为当前宿主的迁移来源；有效检查点会非破坏性复制到新状态根，旧根不会被删除。迁移损坏、中断或目标冲突时不会切换权威状态，修复后可幂等重试。
- 插件禁用、卸载和版本缓存清理不会删除 `NOVA_HOME`。本版本没有自动清理用户状态的入口。
- 新的一次性作用域证明要求 Hook 与 MCP 同时来自 v0.3.0；正在运行的旧会话不会热切换，验收新版本必须新开会话。
- 同一长生命周期宿主进程内的 Nova 多会话并发仍不受支持；每个需要动态检查点的会话应使用独立 Codex 或 Claude Code 进程。
- 已使用兼容软链接的宿主仍须避免与版本化插件同时启用；切换入口后应运行 discovery 校验并新开会话。
- 状态根不可写、检查点无效或压缩握手不完整时，Nova 不会把旧状态提升为权威恢复依据，但普通对话和宿主原生压缩仍可继续。
