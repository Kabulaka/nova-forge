# Nova Forge v0.3.1

> 修复 Claude Code marketplace 安装的二次远程克隆

## Overview

Nova Forge v0.3.1 修复 Claude Code 从同仓库 marketplace 安装插件时再次克隆 GitHub 仓库的问题。插件现在直接复用已经添加的 marketplace 内容，公开仓库安装不再额外依赖 GitHub SSH 主机信任或 SSH Key。Codex 的 HTTPS marketplace 安装契约保持不变。

## Highlights

### Claude Code Marketplace Installation

Claude Code marketplace 中的 Nova Forge 插件 source 改为同仓库相对路径。添加 marketplace 后，安装 `nova-forge@nova-forge` 会直接使用已下载内容，不再发起第二次远程克隆。

### Dual-Host Source Validation

版本同步与结构校验现在分别锁定两个宿主的原生 source 契约：Claude Code 使用同仓库相对路径，Codex 继续使用带版本标签的显式 HTTPS URL。

## Fixes

- 修复 Claude Code 在 marketplace 已成功添加后，安装插件仍可能因 `Host key verification failed` 失败的问题。
- 防止版本同步脚本向 Claude Code 的相对 source 写入无效版本引用。
- 增加双宿主 marketplace source 回归测试，避免 Claude 与 Codex 的安装语义被机械同步。

## Installation

### Codex CLI

```bash
codex plugin marketplace add Kabulaka/nova-forge --ref v0.3.1
codex plugin add nova-forge@nova-forge
```

### Claude Code

```text
/plugin marketplace add Kabulaka/nova-forge
/plugin install nova-forge@nova-forge
```

## Requirements

- Node.js 22.5 或更高版本；插件不会自动安装 Node.js 或 Bun。
- 支持插件 marketplace 的 Codex CLI，或 Claude Code 2.1.233 及兼容版本。
- 安装后审阅并信任插件 Hook，并在切换版本后新开宿主会话。

## Upgrade Notes

- Claude Code 用户先更新 `nova-forge` marketplace，再更新或重新安装 `nova-forge@nova-forge`；此前因 SSH 主机校验失败而未安装成功的用户可直接重试安装。
- Codex 用户把 marketplace 固定引用更新为 `v0.3.1`，重新安装或刷新插件后新开会话。
- 本版本不改变检查点 schema、状态根、迁移或 Hook/MCP 运行语义，现有 `NOVA_HOME` 数据无需转换。
- 同一长生命周期宿主进程内的 Nova 多会话并发仍不受支持；每个需要动态检查点的会话应使用独立 Codex 或 Claude Code 进程。
- 已发布的 `v0.3.0` 标签和资产保持不可变。
