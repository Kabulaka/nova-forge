# Nova Forge v0.6.2

> 修复业务需求文档的默认保存路径

## Overview

Nova Forge v0.6.2 修复 `nova-requirements` 在用户要求创建或保存业务需求文档、但未指定目标文件时缺少默认落点的问题。需求文档现在默认保存到目标项目的 `.nova/PRODUCT_REQUIREMENTS.md`；用户明确指定其他目标文件时仍遵循用户选择。

## Highlights

### 明确的默认保存位置

`nova-requirements` 现在明确区分默认路径与显式路径：未指定目标文件时使用 `.nova/PRODUCT_REQUIREMENTS.md`，已指定目标文件时不覆盖用户选择。澄清阶段仍默认只在对话中推进，用户没有要求保存时不会写文件。

### 回归保护

插件结构测试新增精确断言，防止后续维护再次移除需求文档的默认保存路径。

## Installation

### Codex CLI

```bash
codex plugin marketplace add Kabulaka/nova-forge --ref v0.6.2
codex plugin add nova-forge@nova-forge
```

### Claude Code

```text
/plugin marketplace add Kabulaka/nova-forge
/plugin install nova-forge@nova-forge
```

## Requirements

- Node.js 22.5 或更高版本；插件不会自动安装 Node.js 或 Bun。
- 支持插件 marketplace 的 Codex CLI，或 Claude Code 2.1.233 及兼容版本。
- 安装后审阅并信任插件 Hook，并在升级后新开宿主会话。

## Upgrade Notes

- Codex 用户把 marketplace 固定引用更新为 `v0.6.2`，重新安装或刷新插件后新开会话。
- Claude Code 用户先更新 `nova-forge` marketplace，再更新或重新安装 `nova-forge@nova-forge`，随后新开会话。
- 本次升级不移动或重写既有需求文档；只有后续未指定目标文件的新建或保存操作使用默认路径。
- 用户明确指定的需求文档路径保持优先。
